# 수아의 공부방 배포 전 권위·오프라인 강화 설계

**상태:** A안 승인

**목표:** 라이브 Synology 배포 전에 기기 수명주기, 서버 권위 날짜·계획, 유효 학습 세션, 오프라인 학습과 별 원장의 인과 순서를 일관되게 만든다.

## 1. 설계 원칙

1. 서버만 오늘 날짜, 발급된 학습 계획, 별 잔액과 차감 결과를 확정한다.
2. 네트워크가 끊겨도 당일 학습은 이어가되, 대기 상태는 확정 잔액과 분리한다.
3. 순서가 불확실한 오프라인 데이터는 수아에게 불리한 차감을 만들지 않는다.
4. 완전히 오프라인에서 시작한 학습에는 무반응 별 차감을 적용하지 않는다.
5. 기기 해제와 로그아웃은 오프라인 학습 권한을 제거하지만 미전송 학습 기록은 삭제하지 않는다.
6. 인증 토큰, PIN, 비밀번호, 음성 파일, 전체 전사문과 원문 세션 토큰은 캐시하지 않는다.

## 2. 기기 수명주기

### 보호자 기능

보호자는 로그인 후 언제든 다음 작업을 할 수 있다.

- 현재 브라우저를 수아용 신뢰 기기로 등록한다.
- 등록 기기 목록에서 표시 이름, 등록 시각, 마지막 사용 시각과 상태를 확인한다.
- 기기를 해제한다.
- 보호자/수아 모드를 전환하거나 로그아웃한다.

보호자 대시보드의 기존 다섯 탭은 유지한다. 기기 관리와 역할 전환은 상단 계정 메뉴에서 제공한다.

### 서버 규칙

- 기기 쿠키는 임의의 불투명 토큰이며 서버에는 pepper를 적용한 해시만 저장한다.
- 유효한 학생 세션이 있지만 기기 쿠키가 없거나 서버가 모르거나 세션에 묶인 기기와 다른 경우 `DEVICE_NOT_TRUSTED`를 반환한다. 유효한 세션이 없는 임의의 모르는 쿠키는 `AUTH_REQUIRED`이다.
- 알려진 해제 기기 쿠키는 해제 트랜잭션이 학생 세션을 삭제한 뒤에도 cold `/api/auth/me`에서 `DEVICE_REVOKED`를 반환한다. 보호자 세션은 해제로 삭제되지 않는다.
- 해제 시 해당 기기에 묶인 학생 세션과 아직 활성인 학습 세션을 같은 트랜잭션에서 무효화한다.
- 목록 API는 불투명 쿠키, 해시와 내부 식별자를 반환하지 않는다.

### 브라우저 저장소 정책

- 로그아웃 또는 기기 해제 시 오프라인 접근 임대, 캐시 계획과 확정 별 스냅샷을 즉시 삭제한다.
- 미전송 시도와 무반응 이벤트는 데이터 유실 방지를 위해 보존한다.
- 보존 큐는 재등록·학생 PIN 로그인 전에는 열람·수정·동기화할 수 없다.
- `DEVICE_REVOKED` 수신 시 메타 상태를 `device-action-required`로 바꾸고 동일 정책을 적용한다.

해제 기기의 보존 큐는 옛 기기 계획을 새 기기 권한으로 직접 제출하지 않는다. 기기 조치 화면은 보호자 비밀번호를 먼저 다시 확인하고, guardian-only 등록 API로 현재 브라우저를 다시 등록한 뒤 보호자 세션을 종료한다. 이 복구 흐름은 학생 PIN을 재설정하지 않고 기존 4자리 PIN 입력 화면으로 돌아간다. 등록 성공 후 세션 종료 응답을 잃어도 로컬은 fail-closed `auth-required`로 전환한다. 학생 PIN으로 재인증한 뒤에만, 서버가 같은 학생·해제된 원기기·미만료 원계획을 확인하여 현재 기기에 묶인 일회성 복구 계획을 발급한다. 복구 계획은 원계획의 날짜·항목·버전·필수 여부·제출 기한을 그대로 복사하며 새 날짜나 추가 별 획득 기회를 만들지 않는다. 시도는 복구 계획으로 검증하고, 보존 무반응 기록은 항상 차감 면제로 처리한다.

기기 쿠키만 유실되어 `DEVICE_NOT_TRUSTED`가 된 경우에도 브라우저는 같은 원자적 큐 보존·차단 상태로 전환한다. 새 기기를 등록해도 원계획 기기가 서버에서 아직 활성이라면 복구 계획을 발급하지 않고 `SOURCE_DEVICE_STILL_ACTIVE`로 보류한다. 보호자가 기기 관리에서 원기기를 명시적으로 해제하고 학생이 다시 인증한 뒤에만 위 복구 절차를 진행한다. 보류 상태는 데이터 거절이나 자동 삭제로 취급하지 않는다.

## 3. 서버 발급 계획과 날짜 권위

### 날짜

- 학생용 오늘 계획은 서버가 계산한 `Asia/Seoul` 현재 날짜만 발급한다.
- 학생 API의 날짜 입력은 실제 존재하는 달력 날짜인지 공통 검증기를 통과해야 한다.
- 학생이 임의 과거·미래 날짜로 계획을 만들 수 없다.
- 보호자 미래 계획과 유지보수 과거 날짜는 별도 역할·범위 규칙을 유지한다.

### 계획 발급

새 마이그레이션은 다음 권위 데이터를 추가한다.

- `issued_daily_plans`: 학생, 신뢰 기기, 학습 날짜, 발급 시각, 제출 만료 시각, 오프라인 epoch와 시작 활동 cursor.
- `issued_plan_items`: 발급 계획에 포함된 항목과 당시 콘텐츠 버전.
- `issued_learning_sessions`: 학생, 기기, 항목, 날짜, 발급·활성·제출 만료 시각과 해제 상태.
- `student_activity_cursors`: 학생별 마지막 확정 오프라인 epoch/cursor.
- `offline_batches`: 배치 ID, 기기, epoch, 처리 결과와 idempotency 상태.

현재 날짜 계획을 성공적으로 읽을 때만 발급 행을 만든다. 각 발급 계획의 제출 기한은 다음 KST 날짜 23:59:59까지다. 이 범위는 이미 온라인에서 발급받은 어제 계획의 재연결 제출만 허용한다.

`issued_daily_plans`는 일반 당일 계획과 복구 계획을 구분한다. 일반 계획은 학생·기기·날짜당 하나이고, 복구 계획은 원계획·현재 기기당 하나로 idempotent하다. 복구 계획 발급은 위 기기 수명주기 조건을 모두 만족할 때만 가능하며 원기기 계획 자체의 제출 권한을 새 기기에 이전하지 않는다.

### 시도 검증

온라인 시도와 오프라인 배치는 모두 다음을 만족해야 한다.

- 현재 인증 학생과 신뢰 기기가 발급받은 계획이다.
- 항목과 콘텐츠 버전이 발급 계획에 포함된다.
- `occurredAt`은 발급 계획의 학습 날짜 안에 있다.
- 서버 수신 시각은 발급 계획 제출 기한 이내다.

조건을 만족하지 않으면 별 지급과 시도 저장을 모두 거부한다.

## 4. 유효 학습 세션과 무반응 차감

### 세션 발급

온라인에서 문제를 열 때 `POST /api/student/learning-sessions`가 비인증용 상관 ID를 발급한다. ID만으로는 어떤 API도 호출할 수 없으며 현재 학생 세션과 신뢰 기기 인증이 항상 추가로 필요하다.

서버 행은 학생, 기기, 발급 계획, 항목·버전, 발급 시각, 6시간 활성 만료와 제출 만료를 묶는다. 기기 해제 시 즉시 폐기한다.

### 무반응 검증

별 차감 가능한 무반응 이벤트는 다음을 모두 만족해야 한다.

- 유효한 서버 발급 학습 세션이다.
- 학생, 기기, 날짜, 항목과 콘텐츠 버전이 일치한다.
- `idleStartedAt`과 `occurredAt`이 세션 발급 이후이며 6시간 활성 범위 안이다.
- 두 시각 차이는 최소 5분이고, 서버 수신은 제출 만료 안이다.
- 동일 클라이언트 이벤트 ID는 한 번만 처리한다.

완전히 오프라인에서 문제를 연 경우 서버 학습 세션이 없다. 2분·4분 안내와 5분 재개 확인은 로컬에서 표시하지만 별 차감 이벤트는 만들거나 큐에 넣지 않는다. 화면에는 `오프라인에서는 별을 차감하지 않아요`를 표시한다.

온라인에서 발급된 세션이 진행 중 네트워크를 잃은 경우에만 무반응 이벤트를 오프라인 배치에 포함할 수 있다.

## 5. 오프라인 접근과 계획 캐시

### 오프라인 접근 임대

학생 PIN 로그인 성공 응답은 비밀이 아닌 `offlineAccessUntil`을 제공한다. 클라이언트는 다음 조건을 모두 만족할 때만 네트워크 실패를 오프라인 학생 모드로 전환한다.

- 마지막 성공 역할이 학생이다.
- 오프라인 접근 임대가 만료되지 않았다.
- 기기 메타가 `device-action-required`가 아니다.
- 서버가 발급한 현재 KST 날짜의 정제된 캐시 계획이 있다.

임대는 발급 당일 KST 23:59:59와 서버 학생 세션 만료 중 이른 시각까지만 유효하다. 캐시에는 표시 이름, 콘텐츠, 발급 계획 ID, 날짜, 제출 기한과 확정 별 스냅샷만 저장한다. 인증 토큰, 기기 쿠키, PIN, 학습 세션 ID와 음성 전사문은 저장하지 않는다.

### 임시 완료

- 오프라인 정답은 `provisional` 완료로 표시하고 다음 문제로 이동할 수 있다.
- 확정 별 잔액에는 합산하지 않으며 `동기화 대기` 수만 별도 표시한다.
- 재연결 후 서버 배치 영수증으로 완료·별·오늘 계획을 정규화한다.
- 서버 거절 항목은 보호자에게 이유를 보여 주고 자동으로 별을 지급하지 않는다.

## 6. 인과 순서가 있는 오프라인 배치

### 클라이언트 저널

기존 시도·무반응 큐를 단일 `activityQueue`로 이전한다. 각 행은 다음 정렬 키를 가진다.

- 서버 발급 계획의 `offlineEpoch`와 시작 `activityCursor`
- `occurredAt`
- 기기 내 단조 증가 `deviceSequence`
- 클라이언트 idempotency ID

큐는 예약 하나당 최대 100개씩 `POST /api/student/offline-batches`로 보낸다. 하나의 sync wake는 시작 시점에 보인 eligible 행을 기준으로 처리 횟수를 유한하게 제한하면서, 성공하는 동안 101번째 행과 후속 authority group까지 연속해 비운다. network/5xx, 401, 기기 조치, terminal 거절이나 recovery hold를 만나면 그 즉시 중단하고 이전 성공 건수만 `sent`에 누적하며 다음 예약을 만들지 않는다. 클라이언트가 임의 정렬을 바꾸지 못하도록 서버가 epoch, 계획, 세션과 시각을 검증한 뒤 다시 정렬한다.

### 서버 처리

배치는 한 SQLite 즉시 트랜잭션에서 처리한다.

1. 배치·각 이벤트 idempotency를 확인한다.
2. 발급 계획, 기기, 날짜, 항목·버전과 학습 세션을 검증한다.
3. `(occurredAt, deviceSequence, clientId)` 순으로 시도와 무반응을 함께 적용한다.
4. 별 0 하한과 하루 무반응 차감 2개 상한을 그 순서에서 계산한다.
5. 영수증, 새 활동 cursor, 계획·별 요약을 함께 커밋한다.

### 여러 기기 충돌

배치의 시작 cursor가 현재 학생 cursor와 다르면 늦게 도착한 epoch로 처리한다.

- 학습 시도와 완료는 검증·idempotency 통과 후 보존한다.
- 해당 배치의 무반응 이벤트는 별을 차감하지 않고 `오프라인 순서 충돌로 차감 면제` 감사 결과로 남긴다.
- 학생에게 불리한 소급 차감이나 기존 원장 재작성은 하지 않는다.
- 영수증은 `ORDER_CONFLICT_WAIVED`를 반환하고 보호자 기록에 표시한다.

이 규칙은 여러 기기의 정확한 과거 전역 순서를 추측하지 않고, 데이터 보존과 아동 우선 공정성을 함께 지킨다.

## 7. API와 오류 계약

추가·변경 API:

- `GET /api/guardian/devices`
- `POST /api/guardian/devices/current`
- `POST /api/guardian/devices/:deviceId/revoke`
- `POST /api/auth/session/end`
- `POST /api/student/learning-sessions`
- `POST /api/student/recovery-plans`
- `POST /api/student/offline-batches`

주요 오류 코드:

- `DEVICE_NOT_TRUSTED`, `DEVICE_REVOKED`
- `OFFLINE_ACCESS_EXPIRED`
- `PLAN_NOT_ISSUED`, `PLAN_SUBMISSION_EXPIRED`
- `LEARNING_SESSION_INVALID`, `LEARNING_SESSION_EXPIRED`
- `CURRENT_DAILY_PLAN_REQUIRED`는 KST 자정 경계에서 현재 당일 계획을 다시 읽은 뒤 같은 예약 배치를 재시도하는 비종결 전제 조건이다.
- `SOURCE_DEVICE_STILL_ACTIVE`는 보호자가 원기기를 해제할 때까지 보존 큐를 유지하는 비종결 보류 상태다.
- `ORDER_CONFLICT_WAIVED`는 성공 영수증 상태이며 오류가 아니다.

`session/end`는 현재 역할 세션만 종료하고 권한을 높이지 않는다. 학생에서 보호자로 전환할 때는 보호자 비밀번호를 다시 입력하고, 보호자에서 학생으로 전환할 때는 등록 기기의 4자리 PIN을 다시 입력한다. 역할 전환이라는 이름으로 자격 증명 없이 세션 역할을 바꾸는 API는 만들지 않는다.

모든 `/api/auth`, `/api/student`, `/api/guardian` 응답은 `Cache-Control: no-store`를 사용한다. 공개 건강 확인은 별도의 짧은 캐시 금지 정책을 사용한다.

## 8. PWA와 사용자 경험

- 서비스 워커는 해시 정적 자산, 앱 셸, Apple 아이콘, 192px·512px 아이콘만 precache한다.
- `/api/*`, 인증 JSON, 계획 JSON과 쿠키는 Cache Storage에 넣지 않는다.
- 오프라인 배너는 확정 별과 대기 학습을 구분해 표시한다.
- 축하 표시는 최대 1초이며 reduced motion에서는 이동 효과가 없다.
- 로그아웃·역할 전환·기기 등록/해제 버튼은 최소 48px 터치 영역을 사용한다.

## 9. 마이그레이션과 호환성

- IndexedDB 버전을 올리고 새 권위 완비 기록은 `activityQueue`를 사용하며, 기존 `attemptQueue`와 `idleEventQueue`는 한 업그레이드 트랜잭션에서 `legacyActivities`로 이전한다.
- 이전 큐에는 발급 계획 ID·epoch·cursor가 없고 이전 시도에는 신뢰할 `occurredAt`도 없으므로 먼저 로컬 `legacyActivities`에 격리하며 값을 꾸며내지 않는다. 재인증 후 서버가 발급한 같은 당일 계획에 항목·버전이 일치하는 시도만 재연결 시각으로 검증하고, 이전 무반응은 같은 당일·항목 일치 시 발급 스냅샷 버전을 사용해 `ORDER_CONFLICT_WAIVED`로만 처리한다. 나머지는 `LEGACY_AUTHORITY_UNAVAILABLE`로 로컬 보호자 확인 목록에 보존한다.
- 기존 신뢰 기기는 활성 상태로 유지한다. 장치 목록 표시 이름이 없으면 안전한 기본 이름을 사용한다.
- 기존 오늘 계획과 별 원장은 삭제하거나 재작성하지 않는다.

## 10. 테스트와 배포 게이트

### 자동 테스트

- 데스크톱 초기 설정 후 Galaxy Tab 등록, PIN 로그인, 역할 전환과 로그아웃.
- 기기 해제 시 학생·학습 세션 무효화와 `DEVICE_REVOKED` 계약.
- 해제로 학생 세션이 삭제된 뒤 cold `/api/auth/me`가 즉시 `DEVICE_REVOKED`를 반환하고, 유효 세션의 모르는 기기는 `DEVICE_NOT_TRUSTED`, 임의의 미인증 쿠키는 `AUTH_REQUIRED`를 반환한다.
- 복구 화면에서 보호자 재인증 전에는 등록 API를 호출하지 않고, 등록 후에는 PIN 재설정 없이 기존 학생 PIN으로 돌아간다.
- 오프라인 임대 유효/만료/로그아웃/해제와 콜드 스타트.
- 당일 서버 계획만 발급, 불가능·과거·미래 날짜 거절, 발급된 어제 계획의 제한적 제출.
- 위조·다른 항목·다른 기기·만료 학습 세션의 무반응 거절.
- 별 0에서 10:00 무반응 후 10:05 완료를 배치 처리해 0원 감사 뒤 +1, 최종 1.
- 101개 이상과 서로 다른 authority group을 하나의 sync wake에서 연속 처리하되, 후속 retry/auth/device/terminal 결과는 이전 성공 건수를 보고하고 정확히 중단한다.
- 여러 항목 교차 이벤트, 재시도, 일일 차감 상한과 두 기기 cursor 충돌 차감 면제.
- API `no-store`, PWA 아이콘 precache와 `/api` 제외, 1초 축하.

### 실제 운영 게이트

수정 코드의 전체 검토가 통과한 뒤에만 Synology 배포를 재개한다. Docker 스모크, Galaxy Tab, 두 기기, 오프라인/재연결, 기기 해제, 백업/복원, DSM 작업, 외부 443 전용 노출을 모두 실제 증거로 기록한다.
