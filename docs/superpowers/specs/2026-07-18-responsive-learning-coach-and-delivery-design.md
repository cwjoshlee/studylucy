# 수아의 공부방 반응형 학습·차나핑 코치·자동 배포 설계

## 상태

- 작성일: 2026-07-18
- 적용 브랜치: `codex/platform-foundation`
- 승인된 방향: 초등 1학년 후반 연산, 명시적인 국어 녹음 경험, 차나핑의 짧은
  실시간 코칭, 유형별 신뢰 기기 한도, GitHub 병합 후 NAS 자동 배포

## 1. 목표

수아가 Galaxy Tab에서 국어 읽기와 연산을 막힘 없이 이어가도록 다음 네 가지를
개선한다.

1. 국어 음성 인식의 상태, 중지, 종료와 다음 문제 전환을 분명하게 만든다.
2. 수학을 읽기 문장제가 아닌 초등 1학년 후반의 계산 연습으로 바꾼다.
3. 차나핑이 하단에서 정답·오답·무반응에 짧게 반응하되, 학습을 방해하거나
   수아를 위축시키지 않게 한다.
4. 테스트 기기를 포함해 여러 기기의 진도 공유와 NAS 배포를 운영자가 매번
   수동으로 처리하지 않아도 되게 한다.

이 설계는 기존 서버 권위, 오프라인 보존, 별 원장, 5분 무반응 차감의 감사 기록과
외부 HTTPS 443만 공개하는 배포 경계를 유지한다.

## 2. 범위와 비범위

### 이번 범위

- 국어 음성 인식 UX와 자동 다음 문제 전환
- 기존 친구 이름을 `별토끼 버니`, `아기용 밀키`로 변경
- 기존 `math-story`와 호환되는 계산 확장, 계산 화면, 큰 숫자 키패드와 초기 연산 콘텐츠
- 사용자 제공 참고 이미지와 페르소나를 바탕으로 한 차나핑 하단 플로팅 코치
- 선택적 저비용 LLM 차나핑 문구 생성과 안전한 로컬 대체 문구
- 신뢰 기기의 유형별 등록 한도와 관리 화면
- GitHub Actions, GitHub Container Registry(GHCR), NAS pull 방식의 자동 배포

### 이번 비범위

- 브라우저의 원시 음성 파일 저장·전송·재생
- 수아가 LLM과 자유롭게 대화하는 채팅창
- 음성 합성, 카메라, 손글씨 OCR
- 초등 2~3학년 전체 연산 콘텐츠의 일괄 추가
- 외부 SSH, DSM, Docker API 또는 새 포트 공개
- PR 갱신·임의 브랜치 변경의 자동 운영 배포

## 3. 국어 읽기: 녹음이 아니라 명시적인 음성 인식 세션

현재 브라우저 기능은 음성 파일을 녹음하는 `MediaRecorder`가 아니라 Chrome의
음성 인식이다. 화면에서도 이를 숨기지 않고 `읽는 소리를 듣고 있어요`로
표시한다. 음성 파일과 전체 전사문은 저장하거나 LLM에 보내지 않는다.

### 상태와 조작

| 상태 | 화면 | 허용 조작 |
|---|---|---|
| 준비 | `읽기 시작` | 시작, 낱말 힌트, 직접 입력 |
| 듣는 중 | 빨간 점, 경과 시간, `듣고 있어요` | `읽기 멈추기` |
| 마무리 | `읽은 내용을 확인하고 있어요` | 중복 시작 금지 |
| 통과 | 짧은 성공 표시와 차나핑 반응 | 1.5초 뒤 자동 다음 문제 |
| 재시도 | 놓친 낱말과 재시도 버튼 | 다시 읽기, 직접 입력 |

- 첫 음성 결과 뒤 3초 동안 새 결과가 없으면 인식을 마무리한다.
- 시작 뒤 결과가 전혀 없으면 15초에 안내를 표시하고, 전체 세션은 최대 45초에
  멈춘다.
- 항상 명시적 `읽기 멈추기` 버튼을 제공한다. 브라우저가 인식을 조기에 끝내도
  버튼·상태는 안전하게 준비 상태로 돌아간다.
- 국어 정답은 서버 저장 영수증이 `completed=true`로 확인된 경우에만 1.5초 후
  `onNext()`를 한 번 호출한다. 오프라인의 로컬 정답은 `동기화 대기`임을 먼저
  보인 뒤 같은 방식으로 다음 문제로 이동한다.
- 음성 인식 비지원·권한 거부·빈 전사문에서는 직접 입력 경로를 계속 제공한다.

## 4. 수학: 초등 1학년 후반 계산 연습

사진의 `기적의 계산법 2권` 19단계는 초등 1학년용의 받아올림·받아내림과 세 수
혼합 계산이다. 첫 계산 세트는 이를 기준으로 한다. 교육과정상 두 자리 수 범위의
덧셈·뺄셈과 세 수 계산은 1~2학년군 범위지만, 화면의 기본 난이도는 `1학년 후반`
으로 표기한다.

### 콘텐츠 모델

초기 승인안은 새 판별자인 `kind: "math-calculation"`을 제안했지만, 이전 이미지가
version 3 콘텐츠를 읽을 수 없어 이미지 롤백을 깨뜨리므로 이 결정은 폐기되었다.
현재 계약은 기존 `math-story`의 모든 필드를 유지하고, 엄격한 선택적 `calculation`
확장만 더한다.

```ts
type CalculationExtension = {
  operands: readonly [number, number] | readonly [number, number, number];
  operators: readonly ["+" | "-"] | readonly ["+" | "-", "+" | "-"];
  layout: "horizontal" | "vertical";
};

type MathStoryPayload = {
  kind: "math-story";
  subject: "math";
  // 기존 question, unitLabel, text, readLabel, tokens, hint 필드도 그대로 유지한다.
  answer: number;
  checkHint: string;
  calculation?: CalculationExtension;
  delight?: LearningDelight;
};
```

- `operands.length = operators.length + 1`, 2~3개의 수만 허용한다.
- `calculation` 객체는 선언된 세 필드 외 값을 거부하며, 현재 이미지는
  `isCalculationItem(payload)`로 `math-story` 중 계산형만 식별한다.
- 서버는 payload의 `answer`만 정답 권위로 사용하고 클라이언트가 식을 계산해
  정답을 주장하지 못하게 한다.
- 계산형 `math-story`는 읽기 점수·전사문·읽기 통과를 요구하지 않는다. 기존
  저장 구조의 읽기 필드는 내부 호환 값으로만 유지하고, 국어 읽기 통계에는
  계산 시도를 포함하지 않는다.
- 이전 문장제 `math-story`와 과거 시도는 계속 읽고 재생할 수 있다. 새로운
  기본 seed와 이후 LLM 생성은 계산형을 사용한다.
- 이전 이미지는 선택적 확장을 무시하고 보존된 문장제 필드로 version 3 레코드를
  계속 읽을 수 있다. 따라서 실패 배포에서는 DB나 콘텐츠를 되돌리지 않고
  이미지만 되돌리는 롤백을 보장한다.

### 화면

- 수학에는 음성 인식, 낱말 힌트, 수동 전사 입력을 표시하지 않는다.
- 가로형은 `13 + 9 + 4 = ?`처럼 큰 식을 한 줄로, 세로형은 일의 자리가 맞춰진
  누적 계산 카드로 보여 준다.
- Galaxy Tab 가로 화면의 답 입력은 운영체제 키보드가 아닌 0~9, 지우기, 답 확인
  버튼을 가진 48px 이상의 큰 숫자 키패드다.
- 첫 오답은 계산식과 `checkHint`를 보여 주고, 이후에는 부호 확인 → 첫 계산 →
  차례 계산의 한 단계만 추가한다. 정답과 별 지급은 기존 서버 영수증에서만
  확정한다.

초기 세트는 가로형 세 수 덧셈·뺄셈과 세로형 누적 덧셈·뺄셈을 섞어 10개 이상
제공한다. 수는 음수가 되지 않고 답은 두 자리 수 범위에 머문다.

## 5. 친구 이름과 차나핑

### 기존 친구

내부 ID와 이전 콘텐츠 호환성을 위해 `lumi`, `bongbong` 식별자는 유지한다.
표시 이름·대체 설명·대사·초기 콘텐츠의 등장 이름은 다음과 같이 바꾼다.

- `별토끼 루미` → `별토끼 버니`
- `아기용 봉봉` → `아기용 밀키`

### 차나핑 역할

차나핑은 수아의 아빠 역할을 하는 별도 코치다. 기존 상단 과목 친구를 대체하지
않고, 학습 카드 하단 오른쪽에 작은 플로팅 카드로 나타난다. 사용자 제공 이미지의
청록색 머리, 반쯤 감긴 눈, 느긋한 표정을 참고한 전용 그림을 사용하며, 눕기·눈
감기·살짝 투명해지기를 reduced-motion 환경에서는 정지 그림으로 바꾼다.

말투는 귀찮음을 표현하는 짧은 `차나~` 말버릇을 사용하되 다음 경계를 가진다.

| 사건 | 허용 반응 예 |
|---|---|
| 정답 | `오… 맞았네. 칭찬하는 것도 귀찮은데, 이건 칭찬이야. 차나~!` |
| 첫 오답 | `아휴, 부호부터 다시 보자. 차나핑이 누워 있기 전에!` |
| 반복 오답 | `첫 계산부터 한 칸씩. 급하게 누르면 나도 귀찮아져.` |
| 2분 무반응 | `수아야, 나보다 더 가만히 있으면 어떡해… 한 번만 눌러 보자.` |
| 5분 결과 | 서버의 별 차감 사유를 바꾸지 않고 `다시 시작하면 돼.`만 덧붙임 |

금지: 바보·느림·게으름의 낙인, 형제·친구와의 비교, 벌·별 차감 협박, 인격
평가, 외모 평가, 오답 횟수 조롱, 큰 소리·자동 음성. 같은 대사는 4분 안에
반복하지 않는다.

### 표시 규칙

- 차나핑은 학습 열림, 녹음 시작·종료, 정답, 오답, 2분 생각, 4분 확인, 5분 결과,
  다음 문제에서만 갱신한다. 키패드의 모든 누름마다 말하지 않는다.
- 답 확인·음성 결과가 저장 중이면 `잠깐… 기록 확인도 귀찮지만 기다릴게.` 같은
  상태 문구만 보여 주며, 완료나 별을 미리 말하지 않는다.
- 화면 reader에는 하나의 `role=status`만 노출하고, 새 대사는 최대 45자·두 문장
  이하로 제한한다.
- 보호자 설정에서 차나핑 표시를 끌 수 있다. 꺼진 경우에도 학습·별·무반응 규칙은
  바뀌지 않는다.

## 6. LLM 차나핑 문구

### 기본 동작

LLM은 차나핑의 문구만 만들고, 정답·별·무반응 차감·다음 문제의 권위를 갖지
않는다. 호출은 브라우저가 아니라 NAS 서버에서만 수행한다.

- 기본 공급자: `gemini-2.5-flash-lite`
- 대체 공급자: `gpt-5-nano`
- 한 호출의 입력은 사건 종류, 과목, 문제 유형, 재시도 수, 제한된 힌트 종류뿐이다.
  수아 이름, PIN, 음성 전사문, 녹음, 답의 원문, 쿠키, 학습 전체 기록은 보내지
  않는다.
- 출력은 JSON의 `message` 한 필드, 한국어 45자 이하, 최대 두 문장으로 요구한다.
- 서버는 응답 길이·한글·금지 표현·허용 사건을 검증한다. 실패, 시간 초과, 제공자
  오류, 필터 실패 시에는 같은 사건의 사전 승인 로컬 문구를 즉시 보여 준다.
- API 키와 보호자 사용 설정이 모두 갖춰진 경우에만 LLM 호출을 켠다. 첫 설치와
  키 미설정 상태의 기본값은 로컬 문구이며, 보호자 화면에서 사용 여부·하루 호출 수·
  월 비용 상한을 조정한다. 상한 도달 뒤에는 로컬 문구만 사용한다.

### API 키와 저장

- 보호자 `AI 설정` 화면에서 공급자·모델·사용 여부·비용 상한과 API 키를 관리한다.
- 키는 표시·재조회하지 않고 NAS의 별도 `LLM_ENCRYPTION_KEY`로 AES-256-GCM 암호화해
  SQLite에 저장한다. 복호화 키는 mode 600 `.env`에만 둔다.
- 키를 바꾸거나 삭제하면 이전 암호문은 즉시 쓸 수 없게 한다. 로그, 브라우저
  응답, 백업 화면, LLM 프롬프트에 키를 넣지 않는다.
- 무료 API 등급은 테스트에서만 사용할 수 있다. 가족 학습 데이터의 운영 호출은
  유료 API를 기본으로 하여 제공자가 입력을 모델 개선에 쓰지 않는 계약을 선택한다.

### 비용 가드레일

2시간에 약 60문제와 재시도를 합쳐 80회, 호출당 입력 400토큰·출력 45토큰으로
제한한다. 이때 Gemini 2.5 Flash-Lite는 약 7원, GPT-5 nano는 약 5원 수준이다.
실제 비용은 모델·환율·출력 길이에 따라 달라지므로 보호자 화면은 공급자의 실제
응답 사용량과 예상 비용을 누적해 표시한다. 기본 월 상한은 1,000원이다.

기존의 문제 생성과 보호자 보고서용 고성능 모델은 차나핑 실시간 문구와 분리한다.
차나핑은 한 공급자만 호출하며 두 모델 상호 감리나 웹 검색을 하지 않는다.

## 7. 신뢰 기기 정책

활성 신뢰 기기는 다음 유형별 한도를 가진다.

| 유형 | 코드 | 한도 |
|---|---|---:|
| 태블릿 | `tablet` | 3 |
| 휴대폰 | `phone` | 3 |
| Mac | `mac` | 1 |
| Windows PC | `windows` | 2 |

합계는 최대 9대다. 보호자는 현재 브라우저를 등록할 때 이름과 유형을 확인한다.
브라우저 user-agent는 편의를 위한 제안만 할 뿐 서버 권위가 아니다.

- 같은 활성 기기의 재등록은 새 슬롯을 쓰지 않는 idempotent 동작이다.
- 해제된 기기는 한도에 포함하지 않는다. 해제 시 기존 학생 세션·학습 세션·오프라인
  권한을 기존 계약대로 폐기한다.
- 현재 배포 DB의 유형 없는 활성 기기는 계속 사용할 수 있으며, 보호자 화면에서
  `유형 확인 필요`로 한 번만 분류한다. 이 기기는 분류 전 새 유형 슬롯을 차지하지
  않지만 새 기기를 추가하기 전에 모두 분류해야 한다.
- 한도 초과는 `DEVICE_TYPE_LIMIT_REACHED`와 `태블릿은 최대 3대예요. 사용하지 않는
  기기를 먼저 해제해 주세요.` 같은 유형별 안내를 반환한다.
- 보호자 목록은 유형, 활성 개수/한도, 등록·마지막 사용 시각, 상태와 해제 동작을
  표시한다. 토큰·해시·내부 ID는 계속 노출하지 않는다.

## 8. GitHub에서 NAS까지의 자동 배포

공개 GitHub 저장소와 가족 NAS에서는 NAS를 GitHub self-hosted runner로 쓰거나,
Docker 권한을 가진 수신 웹훅을 외부 443에 열지 않는다. 대신 NAS가 외부로만
연결하는 pull 기반 배포를 사용한다.

```text
main 병합
  → GitHub Actions: 검사·다중 아키텍처 이미지 빌드
  → ghcr.io/cwjoshlee/studylucy:main 갱신
  → NAS 5분 예약 작업: 새 digest 확인
  → SQLite 백업 → pull → app 교체 → 내부 health 확인
  → 실패: 이전 검증 이미지로 복귀, data 보존, 실패 로그 기록
```

### GitHub Actions

- 모든 PR과 `main` push에서 Node 22의 `npm run check`를 실행한다.
- workflow 전체에 workflow/ref별 concurrency를 적용한다. 새 `main` push는 실행
  시작 시점부터 이전 `main` workflow 전체를 취소하고, 서로 다른 PR/ref는 같은
  그룹을 공유하거나 서로 취소하지 않는다.
- 이미지는 검사 성공 뒤 `main` push에서만 GHCR에 게시한다.
- `linux/amd64`와 `linux/arm64` manifest를 함께 게시해 NAS CPU에 맞는 이미지를
  선택한다.
- `main` 태그 외 커밋 SHA 태그와 OCI labels(source SHA, build time)를 기록한다.
- 배포 작업은 GitHub-hosted runner에서만 실행한다. NAS를 runner로 등록하지 않는다.

### NAS pull 작업

- 운영 Compose는 소스 `build` 대신 GHCR 이미지 digest를 참조한다. 데이터·백업·`.env`
  는 계속 `/volume1/docker/sua-learning`에 남는다.
- DSM Task Scheduler가 5분마다 `pull-deploy.sh`를 실행한다. 이 스크립트는 잠금 파일로
  동시 실행을 막고 새 이미지가 없으면 종료한다.
- 새 이미지가 있으면 먼저 앱의 `npm run backup`을 성공시킨 뒤 컨테이너를 교체한다.
  `127.0.0.1:8787/api/health`의 `status=ok`와 Docker health를 모두 확인한다.
- 실패하면 마지막 검증 digest로 한 번 복귀를 시도한다. SQLite `data`를 삭제·초기화·
  자동 복원하지 않으며, 성공하지 못한 배포는 실패 상태와 비밀 없는 tail 로그만 남긴다.
- 공개 포트는 기존 TCP 443 하나뿐이다. DSM 5001, SSH, Docker API, 8787과 배포 훅은
  외부 공개하지 않는다.
- `main`은 운영 배포 대상이다. PR, 임의 브랜치, 수동 GitHub 이미지 태그는 NAS가
  배포하지 않는다.

## 9. 데이터·오프라인·보상 경계

- 계산형 정답도 기존 attempt idempotency, 서버 발급 계획, 학습 세션과 별 원장을
  거친다.
- 차나핑과 LLM은 별을 주거나 빼지 않고, 5분 차감 사유를 변경하거나 숨기지 않는다.
- 여러 신뢰 기기의 plan·cursor 충돌 규칙과 오프라인 순서 충돌 차감 면제는 그대로
  적용한다.
- 콘텐츠 버전은 호환 가능한 math `calculation` 확장과 이름 변경을 새 버전으로 승격한다. 과거 시도와
  발급 계획은 당시 버전을 계속 참조한다.
- 자동 배포 전 backup은 새로운 시도·별 원장·학습 내용을 지우는 롤백 수단이 아니며,
  데이터 복원은 기존 보호자 승인 절차로만 수행한다.

## 10. 검증과 인수 기준

### 자동 테스트

- 음성 인식 시작·명시적 중지·3초 무음 종료·45초 상한·빈 결과·권한 실패
- 국어 서버 정답과 오프라인 로컬 정답의 단 한 번 자동 다음 문제 이동
- 계산형은 음성·읽기 UI 없이 즉시 큰 키패드를 표시하고, 정답·오답·힌트·별 영수증을
  기존 권위 규칙으로 처리
- 엄격한 선택적 `calculation` 확장의 식·연산자·답 검증, 과거 math-story 호환,
  `isCalculationItem` 식별, 국어 통계에서 계산
  시도 제외
- 버니·밀키 이름이 홈·학습·콘텐츠·대체 설명에 일관되게 표시
- 차나핑 각 사건, 말풍선 길이·안전 필터·쿨다운·reduced-motion·로컬 fallback
- LLM 요청에 전사문·PIN·쿠키·학습 원문·키가 없고, API 키 암호화·교체·삭제·비용
  상한이 동작
- 기기 유형별 3/3/1/2 상한, 해제 후 재등록, 기존 유형 미확인 기기, 5개 이상의
  동시 기기 진도 공유
- Docker 이미지 build, Compose image-only 구성, pull-deploy 잠금·무변경·성공·health
  실패 복귀·data 보존

### 실제 운영 인수

- Galaxy Tab 8 Chrome에서 마이크 권한, 녹음 상태, 중지, 자동 종료, 국어 자동 다음
  문제와 수학 키패드 터치 확인
- 태블릿·휴대폰·Mac·Windows의 등록·PIN 로그인·진도 동기화와 기기 해제 확인
- GitHub `main` 병합 후 NAS가 5분 이내 새 SHA 이미지로 건강하게 바뀌는지 확인
- 외부 셀룰러망에서 앱 HTTPS 443만 열리고 DSM·SSH·8787·배포 훅은 닫혀 있는지 확인
- backup·restore 연습과 자동 배포 실패 복귀를 실제 NAS에서 별도 증거로 확인

## 11. 완료 판단

완료는 화면을 새로 꾸미거나 컨테이너를 재시작한 상태가 아니다. 수아가 실제
태블릿에서 녹음 상태를 이해하고 멈출 수 있으며, 국어는 통과 뒤 자연스럽게 다음
문제로 넘어가고, 수학은 사진 수준의 계산을 큰 키패드로 풀며, 차나핑이 안전한
범위에서 반응하고, 등록된 여러 기기와 GitHub 병합 배포가 데이터·보안 경계를
지킨다는 검증 증거가 있어야 한다.
