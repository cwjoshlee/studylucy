# 수아의 공부방 어린이 경험과 별 원장 설계

## 상태

- 작성일: 2026-07-16
- 사용자 승인: 2026-07-16
- 적용 대상: 기존 1단계 플랫폼 기반 계획의 남은 Task 6~11과 선행 별 원장 작업
- 선행 구현: Task 1~5 완료 및 독립 검토 승인

## 1. 목적

수아가 학습을 시작하고 끝까지 이어가도록 오리지널 동물 마법 동화 분위기, 즉각적인 축하와 누적 별 보상을 제공한다. 별은 단순한 화면 장식이 아니라 NAS에 저장되는 감사 가능한 원장으로 관리한다. 학습 완료에는 별을 적립하고, 학습 화면을 켜 둔 채 장시간 아무 활동이 없을 때는 제한적으로 별을 차감한다. 전날 필수 학습을 완료하지 못한 경우에는 보호자가 확인한 뒤 차감할 수 있다.

이 설계는 다음 원칙을 지킨다.

- 아이에게 수치심을 주는 표현을 사용하지 않는다.
- 실제 생각하는 시간과 앱을 보지 않는 시간을 완벽히 구분할 수 있다고 주장하지 않는다.
- 카메라, 시선 추적, 음성 파일과 전체 음성 전사문을 사용하거나 저장하지 않는다.
- 모든 별 변동은 사유와 처리 주체가 남는 원장으로 관리한다.
- 자동 차감에는 경고, 하루 상한, 잔액 하한과 보호자 취소 수단을 둔다.
- 저작권이 있는 캐릭터를 복제하거나 이름·상표를 사용하지 않는다.

## 2. 어린이용 시각 경험

### 오리지널 캐릭터

학생 화면에는 둥근 형태의 파스텔 동물 마법 친구를 사용한다. 기본 콘셉트는 작은 망토와 별 지팡이를 가진 `별토끼 마법 친구`다. 기존 상업 캐릭터의 얼굴, 색 배치, 소품, 이름이나 고유 실루엣을 재현하지 않는다.

캐릭터의 역할은 다음으로 제한한다.

- 오늘의 학습 시작 인사
- 힌트와 무반응 안내
- 정답 및 활동 완료 축하
- 별 적립·차감 이유의 친절한 설명
- 다음 활동으로 이동하는 짧은 격려

### 축하 연출

- 필수 학습 완료 시 별빛과 캐릭터 축하를 1초 이내로 표시한다.
- 전체 화면을 막거나 다음 조작을 지연시키지 않는다.
- 소리를 자동 재생하지 않는다.
- `prefers-reduced-motion: reduce`에서는 이동·폭발 효과를 없애고 색상, 아이콘과 문구만 바꾼다.
- 오답에는 별을 빼지 않으며 `한 번 더 생각해 보자`, `힌트를 눌러도 괜찮아` 같은 문구를 사용한다.

## 3. 오늘의 필수 학습

기본 필수 학습량은 한국 시간 기준 하루 국어 2개와 수학 2개, 총 4개다.

- 서버가 날짜별 결정적 순서에서 과목별 앞의 2개를 필수 항목으로 지정한다.
- 같은 날짜와 같은 콘텐츠 집합에서는 모든 기기가 같은 필수 항목을 받는다.
- 보호자는 후속 관리 화면에서 날짜별 개수를 변경하거나 쉬는 날로 지정할 수 있다.
- 필수 항목의 콘텐츠 버전이 바뀌거나 게시 취소되면 서버가 현재 게시 버전으로 계획을 재검증한다.
- 이미 완료한 필수 항목은 새로 지급하지 않되 완료 상태와 별 지급 기록을 유지한다.

`TodayPlan`에는 `requiredItemIds`와 현재 별 요약을 추가한다. 오늘의 학습 화면은 필수 4개를 우선 표시하고 나머지 게시 콘텐츠는 선택 학습으로 분리한다.

## 4. 별 적립 규칙

- 필수 학습 1개를 최종 완료하면 별 1개를 적립한다.
- 읽기 문제는 서버의 읽기 통과 규칙을 충족해야 완료된다.
- 수학 문제는 읽기 통과 후 서버 정답 검사를 통과해야 완료된다.
- 같은 학생, 학습일과 항목 조합은 한 번만 별을 지급한다.
- 같은 풀이 ID 재전송, 새 풀이 ID로 재시도 또는 오프라인 재동기화가 중복 별을 만들지 않는다.
- 선택 학습은 1차 구현에서 별을 지급하지 않는다.
- 보호자는 사유를 입력해 칭찬 별을 수동 추가할 수 있다.

## 5. 무반응 감지와 자동 차감

### 활동으로 인정하는 입력

다음 동작은 무반응 타이머를 초기화한다.

- 화면 터치와 키보드 입력
- 답 선택 또는 숫자 입력
- 읽기 시작·중지 조작과 음성 인식 결과 이벤트
- 힌트 열기
- `계속하기` 또는 `생각 중이에요` 선택
- 문제 이동과 다시 듣기·다시 읽기 같은 명시적 학습 조작

단순 애니메이션 재생, 네트워크 응답, 서비스 워커 동작은 사용자 활동으로 세지 않는다.

### 시간 규칙

- 2분 무반응: 캐릭터가 힌트 사용을 안내한다.
- 4분 무반응: `계속하기`와 `생각 중이에요` 확인을 표시한다.
- 5분 무반응: 현재 학습을 일시정지하고 별 1개 차감 이벤트를 서버에 보낸다.
- 무반응 자동 차감은 학생당 한국 날짜 기준 하루 최대 2개다.
- 잔액이 0이면 별은 내려가지 않지만 `잔액 부족으로 실제 차감 0개` 감사 기록을 남긴다.

### 타이머 중지 조건

- 문서가 숨김 상태가 될 때
- 브라우저가 백그라운드로 이동할 때
- 화면이 잠기거나 앱이 일시 중지될 때
- 네트워크 요청 때문에 UI 입력이 잠긴 동안
- 축하 또는 결과 화면이 표시되는 동안

다시 활성화되면 이전 숨김 시간을 합산하지 않고 타이머를 새로 시작한다. 카메라나 시선 정보로 활동 여부를 판단하지 않는다.

### 서버의 권위

브라우저는 `idleEventId`, 학습 세션, 항목, 시작·발생 시각을 보고한다. 서버는 다음을 확인한 뒤 차감한다.

- 인증된 학생과 현재 신뢰 기기
- 이벤트 ID 중복 여부
- 해당 날짜의 자동 차감 횟수
- 유효한 학습 세션과 항목
- 발생 시각의 합리적인 순서

브라우저 타이머가 차감을 요청하지만 최종 별 잔액과 하루 상한은 서버만 결정한다. 이는 가정용 동기화와 중복 방지를 위한 것이며 감시 또는 부정행위 탐지 시스템이 아니다.

## 6. 전날 미완료 차감 후보

- 한국 시간 다음 날 오전 6시에 전날 계획을 마감한다.
- 완료하지 못한 필수 항목 1개당 별 1개의 차감 후보를 만든다.
- 하루 차감 후보는 최대 2개다.
- 후보는 즉시 잔액에 반영하지 않는다.
- 보호자가 `승인`, `수량 수정 후 승인`, `면제` 중 하나를 선택한다.
- 아픈 날, 여행, 휴일과 보호자 판단에 따른 면제가 가능하다.
- 승인 시점 잔액이 부족하면 가능한 수량만 차감하고 요청량과 실제량을 함께 기록한다.

오전 6시 작업은 idempotent한 일일 유지보수 명령으로 실행한다. DSM 작업 스케줄러가 명령을 호출하고, 앱 시작 시 최근 미처리 날짜를 재검사해 NAS가 꺼져 있던 날도 중복 없이 보완한다.

## 7. 별 원장과 감사 로그

### 적용된 원장 이벤트

`star_events`는 삭제하거나 기존 금액을 수정하지 않는 append-only 기록이다.

각 이벤트는 다음을 가진다.

- 이벤트 ID와 학생 ID
- 별 증감량과 적용 후 잔액
- 사유 코드와 당시 표시한 한국어 설명
- 발생 시각과 한국 학습일
- 관련 항목, 풀이, 계획, 무반응 이벤트 또는 교환 요청 ID
- 처리 주체: `system` 또는 `guardian`
- 기기 또는 보호자 세션의 감사 식별자
- 원본 이벤트를 취소한 경우 원본 이벤트 ID
- 중복 방지를 위한 고유 출처 키

사유 코드는 최소 다음을 포함한다.

- `REQUIRED_ITEM_COMPLETED`
- `IDLE_TIMEOUT`
- `MISSED_DAILY_PLAN`
- `GUARDIAN_BONUS`
- `GUARDIAN_ADJUSTMENT`
- `REWARD_REDEMPTION`
- `REVERSAL`
- `NO_BALANCE_AUDIT`

잘못된 원장 이벤트는 삭제하지 않는다. 보호자가 취소하면 원본의 실제 증감량과 반대 부호인 요청량을 가진 `REVERSAL` 이벤트를 추가하고 취소 사유를 기록한다. 취소 시점 잔액이 요청량보다 적으면 잔액까지만 실제 차감하고, 요청량과 실제량을 모두 남긴다. 실제 차감량이 0이어도 원본과 연결된 `REVERSAL`로 기록하며 해당 원본은 한 번 취소된 것으로 처리한다.

### 미완료 승인 기록

`pending_star_adjustments`는 미완료 차감 후보를 저장한다.

- 상태: `pending`, `approved`, `waived`
- 요청 수량, 승인 수량과 실제 적용 수량
- 계획일과 누락 항목 ID
- 생성·처리 시각
- 처리 보호자와 메모
- 처리 결과 원장 이벤트 ID

동일 계획일과 항목은 한 번만 후보가 생성되도록 고유 제약을 둔다.

### 잔액

현재 잔액은 학생별 원장 이벤트의 합과 일치해야 한다. 쓰기 트랜잭션에서 현재 잔액을 잠금·확인하고 0 미만이 되지 않도록 실제 차감량을 제한한다. 빠른 조회를 위해 별도 잔액 열을 둘 수 있지만 원장 합과의 일치 검사를 제공해야 한다.

## 8. API 경계

학생 API:

- `GET /api/student/stars`: 현재 잔액, 오늘 적립·차감, 최근 학생용 설명
- `POST /api/student/idle-events`: idempotent 무반응 차감 요청
- 기존 오늘 계획과 풀이 응답에 필요한 별 요약과 신규 적립 결과 포함

보호자 API:

- `GET /api/guardian/stars`: 기간별 전체 원장과 필터
- `GET /api/guardian/star-adjustments`: 미완료 차감 후보
- `POST /api/guardian/star-adjustments/:id/approve`
- `POST /api/guardian/star-adjustments/:id/waive`
- `POST /api/guardian/stars/manual`: 수동 추가·차감
- `POST /api/guardian/stars/:eventId/reverse`: 원장 이벤트 취소

모든 변경 API는 기존 출처 검사, 가족 인증과 역할 검사를 적용한다. 학생은 원장 전체, 보호자 메모와 교환 관리 정보를 볼 수 없다.

## 9. 학생 화면

### 오늘의 학습

- 상단 또는 우측 진행 카드에 `모은 별`과 오늘 변동을 표시한다.
- 필수 항목에는 별 1개 표시를 붙인다.
- 완료 시 서버가 반환한 신규 적립 여부를 기준으로 한 번만 축하한다.
- 중복 풀이에는 적립 애니메이션을 다시 보여주지 않는다.

### 차감 안내

무반응 차감 후 학습 화면을 일시정지하고 다음과 같이 설명한다.

`5분 동안 학습 활동이 없어서 별 1개가 줄었어요. 준비되면 다시 시작할 수 있어요.`

잔액이 없으면 다음처럼 표시한다.

`5분 동안 학습 활동이 없었어요. 줄어들 별은 없고 기록만 남겼어요.`

학생은 현재 잔액과 직전 변동 사유만 본다. 장기간 차감 내역, 보호자 메모와 승인 후보는 보호자 화면에만 표시한다.

## 10. 보호자 화면

보호자 화면에는 다음을 추가한다.

- 현재 별 잔액
- 기간별 적립·차감·취소 합계
- 사유, 시각, 관련 과목·문제와 처리 주체가 포함된 원장
- 오전 6시에 생성된 미완료 차감 후보와 승인·수정·면제 동작
- 수동 칭찬 별과 조정
- 잘못된 이벤트의 취소와 취소 사유 입력

필터는 날짜, 적립·차감, 사유와 처리 상태를 지원한다. 삭제 버튼은 제공하지 않는다.

## 11. 오프라인과 여러 기기

- 오프라인 풀이 완료와 무반응 이벤트는 IndexedDB 대기열에 저장한다.
- 로컬 화면에는 `동기화 중인 별`을 현재 확정 잔액과 구분해 표시한다.
- 서버는 풀이, 별 적립과 무반응 이벤트의 고유 출처 키로 중복을 제거한다.
- 동기화 후 서버 잔액을 다시 읽어 모든 기기를 정규화한다.
- 인증 만료 시 대기열을 보존하고 재로그인 후 전송한다.
- 신뢰 기기가 해제된 경우 학습 대기열은 보존하되 별 변경 전송을 중지하고 보호자 조치를 안내한다.

## 12. 오류와 안전장치

- 별 변경 실패가 풀이 원본 저장을 잃게 해서는 안 된다. 같은 데이터베이스 트랜잭션에서 가능한 작업은 함께 처리하고, 오프라인 요청은 재시도 가능하게 유지한다.
- 중복 출처 키는 기존 결과를 반환한다.
- 하루 자동 차감 상한을 넘긴 요청은 별을 줄이지 않고 현재 요약을 반환한다.
- 보호자 승인 동시 실행은 한 번만 적용한다.
- 시간대는 `Asia/Seoul` 설정을 사용하고 일광 절약 시간에 의존하지 않는다.
- 별 잔액과 원장 합 불일치는 보호자 화면에 오류로 표시하고 자동으로 기록을 삭제하지 않는다.
- 로그에 비밀번호, PIN, 원문 토큰, 음성, 전체 전사문과 전체 답안을 넣지 않는다.

## 13. 향후 장난감과 소원 교환

이번 추가 범위는 원장과 보호자 조정까지 구현한다. 후속 보상 관리에서는 다음을 원장 위에 연결한다.

- 보호자가 장난감·소원 이름, 설명, 필요한 별과 사용 여부를 설정
- 수아가 교환 요청
- 보호자가 승인·거절 또는 필요 별 수정
- 승인 시 `REWARD_REDEMPTION` 원장 이벤트로 차감
- 구매·이행 완료 상태와 보호자 메모

교환 기능은 별 원장 잔액을 다시 계산하거나 별도 화폐를 만들지 않는다.
