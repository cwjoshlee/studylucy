# 수아의 공부방 플랫폼 설계

- 작성일: 2026-07-15
- 상태: 사용자 승인 설계
- 다음 구현 범위: 1단계 플랫폼 기반

## 1. 요약

`수아의 공부방`은 초등학교 1~3학년 국어와 수학을 연습하는 가족 전용 학습 사이트다. 사이트 주소는 공개 인터넷에서 접근할 수 있지만, 등록된 가족만 로그인할 수 있다. 13인치 갤럭시 탭의 가로 화면을 주 사용 환경으로 삼고 휴대폰과 세로 화면도 지원한다.

서비스는 가정의 Synology NAS에서 컨테이너로 실행한다. Synology DDNS와 HTTPS를 사용하고 외부에는 학습 사이트의 443 포트만 공개한다. 학습 기록, 계획, 보상, 콘텐츠와 보호자 설정은 NAS에 저장한다. 음성 파일과 전체 음성 전사문은 저장하지 않는다.

최종 플랫폼은 다음을 제공한다.

- 수아용 오늘의 학습, 단원 지도, 문제 풀이와 보상 화면
- 보호자용 진도, 문제 편집, 주간 계획, 보상과 난이도 관리
- GPT-5.6 Terra와 Gemini 3.5 Flash를 이용한 신규 문제 생성과 상호 감리
- 적응형 난이도, 오답 유형 보완과 간격 복습
- 매 학습 세트 및 주간 보호자용 AI 보고서

전체 범위는 단계별로 구현한다. 다음 구현 계획은 1단계만 다룬다.

## 2. 목표와 제외 범위

### 목표

1. 집 밖에서도 HTTPS로 안전하게 접속한다.
2. 새 기기는 보호자가 등록하고, 등록된 기기에서는 수아가 4자리 PIN으로 학습한다.
3. 여러 기기에서 같은 진도와 보상을 공유한다.
4. 초등학교 1~3학년 국어와 수학 콘텐츠를 단원과 스킬 단위로 확장할 수 있다.
5. LLM은 신규 문제와 보호자 보고서를 생성하되, 수치 계산과 최종 공개 권한을 갖지 않는다.
6. 보호자는 콘텐츠, 계획, 보상, 분야별 난이도와 AI 비용을 통제한다.

### 제외 범위

- 공개 회원가입과 불특정 다중 사용자 서비스
- 학교용 반·교사·학생 관리
- 음성 파일 보관
- 난독증, 학습 장애 또는 의학적 상태 진단
- LLM이 만든 문제의 자동 공개
- DSM 관리자 화면의 외부 공개
- LLM 제공자에게 수아의 이름이나 전체 답안 이력을 전송하는 기능

## 3. 사용자와 접근 정책

### 수아

- 보호자가 등록한 기기에서 4자리 PIN으로 로그인한다.
- 오늘의 학습, 단원 지도, 문제 풀이, 결과와 보상만 이용한다.
- 보호자 설정과 원시 학습 기록에는 접근하지 못한다.

### 보호자

- 강한 비밀번호로 로그인한다.
- 새 기기 등록과 해제, PIN 변경, 진도 확인, 콘텐츠 관리, 계획, 보상, 난이도, API 키와 비용을 관리한다.
- 생성 문제와 AI 보고서를 승인하거나 수정할 수 있다.

### 공개 방문자

- 로그인 화면 외에는 볼 수 없다.
- 공개 회원가입, 게스트 학습과 콘텐츠 미리보기는 제공하지 않는다.

## 4. 배포 구조

### 네트워크

1. Synology DDNS로 공개 호스트 이름을 만든다.
2. DSM에서 Let's Encrypt HTTPS 인증서를 발급하고 자동 갱신한다.
3. 공유기는 외부 TCP 443만 NAS로 전달한다.
4. DSM 리버스 프록시는 HTTPS 요청을 NAS 내부의 앱 컨테이너 포트로 전달한다.
5. DSM 5001, 컨테이너 포트와 데이터베이스는 외부에 공개하지 않는다.

공인 IP 또는 포트 포워딩이 통신사 CGNAT 때문에 불가능하면 배포를 강행하지 않는다. 별도 도메인과 터널 방식으로 전환할지 사용자 승인을 다시 받는다.

### 애플리케이션

- Node.js 단일 애플리케이션으로 학생 UI, 보호자 UI, API와 예약 작업을 제공한다.
- Synology Container Manager에서 컨테이너로 실행하고 NAS 재시작 후 자동 시작한다.
- 정적 자산은 앱이 직접 제공한다.
- SQLite 데이터베이스와 업로드 가능한 콘텐츠 자료는 NAS 볼륨에 둔다.
- 앱 이미지 교체와 데이터 볼륨 교체를 분리한다.

### 데이터 보존

- SQLite는 WAL 모드를 사용한다.
- 일일 백업은 데이터베이스의 일관된 스냅샷과 설정 내보내기를 만든다.
- 최근 일일 백업 14개와 주간 백업 8개를 순환 보관한다.
- 보호자 화면에서 마지막 성공 백업과 실패 경고를 확인한다.
- 복원 시험은 배포 전과 주요 스키마 변경 후 실시한다.

## 5. 인증과 보안

### 기기 등록과 PIN

1. 새 기기에서는 보호자 비밀번호로 먼저 로그인한다.
2. 보호자가 기기 이름을 확인하고 신뢰 기기로 등록한다.
3. 신뢰 기기 토큰은 서버에는 해시로 저장하고 브라우저에는 안전한 쿠키로 저장한다.
4. 신뢰 기기에서만 4자리 PIN 로그인을 허용한다.
5. 기기 해제 시 해당 기기의 세션과 오프라인 학습 자료를 무효화한다.

### 인증 저장

- 보호자 비밀번호와 수아 PIN은 Argon2id 해시로 저장한다.
- 세션 쿠키는 `Secure`, `HttpOnly`, `SameSite=Strict` 속성을 사용한다.
- 로그인, PIN 확인, 기기 등록과 보호자 변경 API에는 요청 제한을 적용한다.
- 반복 실패 시 지연과 임시 잠금을 적용한다.
- 역할 검사는 모든 보호자 API에서 서버가 수행한다.

### 비밀 정보

- OpenAI와 Google API 키는 보호자만 등록, 연결 시험, 교체와 삭제할 수 있다.
- 키는 AES-256-GCM으로 암호화해 저장한다.
- 암호화 마스터 키는 데이터베이스와 분리한 DSM 비밀 설정 또는 컨테이너 환경 비밀에 둔다.
- UI에는 저장 후 키 전체를 다시 표시하지 않고 마지막 몇 글자와 연결 상태만 보여준다.
- 로그, 백업 메타데이터와 오류 메시지에 키를 남기지 않는다.
- AI 기능은 보호자가 제공자별 API 키를 등록하고 외부 전송 범위를 확인한 뒤 명시적으로 켤 때까지 비활성화한다.

## 6. 학생 경험

### 주 화면

확정된 A안인 `오늘의 학습 중심`을 사용한다.

- 상단: 수아의 공부방, 오늘, 단원 지도, 보상함과 프로필
- 왼쪽: 오늘의 국어·수학 활동과 완료 상태
- 중앙: 지금 할 활동, 큰 학습 본문과 시작 버튼
- 오른쪽: 오늘의 진행률, 주간 보상과 보호자 응원 문구

13인치 갤럭시 탭의 가로 화면에서는 세 영역을 한 화면에 배치한다. 터치 대상의 최소 크기는 48px로 하고, 핵심 읽기 문장은 멀리서도 읽을 수 있는 큰 글자를 사용한다. 세로 화면과 휴대폰에서는 오른쪽 정보를 아래로 이동한다.

### 학습 화면

- 한 화면에는 한 활동만 표시한다.
- 국어는 듣기, 소리 내어 읽기, 어휘, 독해, 문법과 쓰기 문제 유형을 지원한다.
- 수학은 숫자 입력, 객관식, 식 세우기, 문장제, 도형·측정과 자료·규칙 문제 유형을 지원한다.
- 정답 확인 뒤 즉시 피드백과 다시 풀기를 제공한다.
- 학습 중에는 보호자 관리 기능과 불필요한 탐색 요소를 숨긴다.
- 필요한 경우 `쉬웠어요`, `생각했어요`, `어려웠어요` 중 하나로 체감 난이도를 표시한다.

### 보상

- 활동과 주간 계획 완료에 별을 지급한다.
- 보호자가 별 지급 기준과 실제 보상을 설정한다.
- 별 지급은 서버의 결정 규칙으로 계산하며 LLM이 임의로 바꾸지 못한다.

## 7. 보호자 경험

### 메뉴

- 진도 요약
- 학습 기록
- 문제 편집
- 주간 계획
- 보상 설정
- AI 문제 생성
- 난이도 조정
- 생성 작업 현황
- 생성 초안
- 수정 필요
- 승인된 문제
- API 및 비용 설정
- 가족·기기 설정

`LLM 검수함`이라는 이름은 사용하지 않는다. LLM은 문제 생성자이며 보호자가 최종 승인자다.

### 진도 요약

- 계획 달성률, 학습 시간, 완료 활동과 별을 표시한다.
- 국어·수학 및 학년·단원·스킬별 진도를 제공한다.
- 최근 어려워한 스킬과 대표 오답 유형을 보여준다.
- 다음 학습 계획과 마지막 백업 상태를 보여준다.

### 콘텐츠 편집

- 보호자는 문제와 학습 문장을 작성, 수정, 복제, 비공개 처리할 수 있다.
- 게시된 콘텐츠 수정은 새 버전을 만든다.
- 과거 풀이 기록은 당시 콘텐츠 버전을 계속 참조한다.
- 초안, 승인, 게시, 보관 상태를 구분한다.

### 주간 계획과 보상

- 요일별 국어·수학 시간과 활동 수를 설정한다.
- 적응형 추천을 받아들이거나 보호자가 직접 활동을 고정한다.
- 별 목표와 가족이 약속한 실제 보상을 설정한다.
- 계획 변경 기록과 적용 날짜를 남긴다.

## 8. 교육과정과 콘텐츠 모델

콘텐츠는 다음 계층으로 관리한다.

`교육과정 → 학년 → 학기 → 과목 → 단원 → 스킬 → 콘텐츠 항목 → 버전`

각 콘텐츠 항목은 다음 메타데이터를 가진다.

- 문제 유형과 본문
- 정답과 허용 가능한 정답
- 해설과 힌트
- 난이도 1~5
- 선수 스킬
- 대표 오답 유형
- 읽기 길이 또는 계산 단계
- 연습용, 평가용 또는 복습용 구분
- 생성 출처, 모델, 생성 시각과 검증 상태

현재 프로토타입의 한글 읽기와 20 이하 수학 문제는 초기 시드 콘텐츠로 이관한다. 이후 국어와 수학을 초등학교 1~3학년 전체로 확장한다.

## 9. 적응형 평가

### 숙달도

각 스킬은 다음 상태와 0~100 내부 점수를 가진다.

- 시작 전
- 학습 중
- 익숙함
- 능숙함
- 숙달

숙달도 갱신에는 정답 여부, 문제 난이도, 힌트 사용, 풀이 시간, 반복 오답, 학습 후 경과 시간과 체감 난이도를 사용한다. 초기 버전은 한 명의 학습자와 새 문제만으로 통계적 문항 모수를 정밀 추정할 수 있다고 가정하지 않는다. 설명 가능한 가중 규칙으로 시작하고, 충분한 기록이 쌓인 뒤 별도 검증을 거쳐 지식 추적 모델을 도입한다.

### 문제 선택 비율

- 60%: 자주 틀리는 스킬과 오답 유형
- 25%: 간격 복습
- 15%: 다음 난이도 또는 새로운 스킬

최근 성과가 안정적으로 좋아지면 한 단계 어렵게 하고, 연속 오답이 발생하면 난이도를 낮추거나 선수 스킬로 돌아간다. 동일 유형은 기본적으로 연속 3문제를 넘기지 않는다.

### 보호자 난이도 보정

- 자동 적응이 기본값이다.
- 국어는 낱말·소리 읽기, 독해, 어휘·문법, 쓰기 분야로 나눈다.
- 수학은 수와 연산, 문장제, 도형·측정, 자료·규칙 분야로 나눈다.
- 보호자는 각 분야에 `-2`, `-1`, `자동`, `+1`, `+2` 보정값을 설정한다.
- 보정값은 선택 문제 난이도와 LLM 생성 조건에 적용하지만 숙달도 자체를 바꾸지 않는다.
- 결과 난이도는 항상 1~5 범위로 제한한다.
- 한 번에 두 단계 이상 급격히 올리지 않는 안전 설정을 기본으로 켠다.
- 변경 이력, 적용자와 적용 시각을 기록하고 자동 값으로 되돌릴 수 있다.

## 10. AI 문제 생성과 상호 감리

### 모델

- OpenAI `gpt-5.6-terra`
- Google `gemini-3.5-flash`

제공자별 어댑터를 두어 모델 교체가 콘텐츠, 검증과 배치 로직에 영향을 주지 않게 한다.

### 생성 요청

보호자는 다음을 지정한다.

- 학년, 학기, 과목, 단원과 스킬
- 난이도와 문제 유형
- 문제 수
- 특별히 포함할 오답 유형
- 연습, 평가 또는 복습 목적

서버는 수아의 이름과 전체 답안 기록 대신 목표 스킬, 숙달 구간, 오답 유형과 난이도 분포만 모델에 전달한다.

### 배치 흐름

1. 요청 문제 수를 두 모델에 절반씩 배정한다.
2. 홀수 문제의 추가 한 개는 배치마다 모델을 번갈아 배정한다.
3. 각 모델은 정해진 JSON 스키마로 신규 문제를 생성한다.
4. 프로그램이 필수 필드, 중복, 학년 범위와 금지 표현을 검사한다. 객관식·수치형처럼 계산 가능한 문제는 정답도 독립적으로 다시 계산한다. 서술형은 정답을 자동 확정하지 않고 평가 기준 존재 여부를 검사한다.
5. Gemini가 GPT 생성 문제를, GPT가 Gemini 생성 문제를 독립적으로 감리한다.
6. 감리에서 결함이 발견되면 원래 생성 모델이 의견을 반영해 한 번 수정한다.
7. 수정 문제를 다시 프로그램 검사와 상대 모델 감리에 통과시킨다.
8. 통과 문제는 `생성 초안`, 미통과 문제는 `수정 필요`에 둔다.
9. 보호자가 확인, 수정, 승인해야 학습 콘텐츠로 게시된다.

한 제공자가 실패하면 다른 제공자가 자동으로 전체를 대신 만들지 않는다. 작업을 부분 완료로 표시하고 실패한 절반만 재시도한다.

### 품질과 비용 지표

- 모델별 생성 문제 수
- 구조 검사 실패율
- 상대 모델 지적률
- 수정 후 통과율
- 보호자 승인·수정·거절률
- 입력·출력 토큰과 추정 비용

보호자는 일일·월간 비용 한도와 배치당 최대 문제 수를 설정한다. 한도 초과 시 새 작업은 시작하지 않고 경고한다.

## 11. 보호자용 AI 보고서

### 종류

- 매 학습 세트 완료 보고서
- 일요일 주간 종합 보고서

### 생성 원칙

1. 서버가 완료량, 점수, 소요 시간, 숙달도 변화, 오답 유형과 난이도 변화를 계산한다.
2. 모델은 계산된 구조화 자료만 사용해 읽기 쉬운 보고서를 작성한다.
3. 다른 모델이 보고서의 모든 수치와 근거가 입력 자료와 일치하는지 감리한다.
4. 결함이 있으면 작성 모델이 한 번 수정한다.
5. 보호자만 보고서를 열람하며 수정 메모를 남길 수 있다.

API 키가 없거나 비용 한도를 초과하면 서버가 계산한 구조화 학습 요약은 계속 제공하고, LLM이 작성하는 자연어 보고서만 보류한다. AI 장애가 학습과 진도 저장을 막아서는 안 된다.

보고서에는 다음이 포함된다.

- 학습 내용과 완료량
- 새로 익숙해지거나 숙달한 스킬
- 어려웠던 부분과 근거 문제 수
- 난이도 변화와 보호자 수동 보정 여부
- 다음 학습에서 보완할 항목 2~3개
- 주간 계획 조정 제안
- 보호자가 사용할 짧은 지도 문구
- 사용 모델과 생성 시각

보고서는 의학적 또는 발달 진단을 하지 않는다. 수치와 근거가 부족한 단정은 금지한다.

## 12. 주요 데이터 개체

- `Family`: 가족 단위 설정
- `User`: 보호자와 학생 역할
- `TrustedDevice`: 등록 기기와 해시 토큰
- `Session`: 로그인 세션
- `Curriculum`, `Grade`, `Term`, `Subject`, `Unit`, `Skill`: 교육과정 계층
- `ContentItem`, `ContentVersion`: 문제와 버전
- `StudyPlan`, `PlannedActivity`: 주간 계획
- `Attempt`: 한 번의 풀이
- `SkillProgress`: 스킬별 숙달 상태
- `DifficultyOverride`: 보호자 분야별 보정
- `RewardRule`, `RewardLedger`: 별 기준과 지급 기록
- `GenerationJob`, `GeneratedDraft`, `ModelReview`: 생성과 교차 감리
- `ProviderCredential`: 암호화된 API 키와 상태
- `UsageLedger`: 토큰과 비용 기록
- `GuardianReport`: 세트·주간 보고서와 근거 자료
- `AuditEvent`: 보호자 변경과 보안 이벤트

모든 주요 기록은 생성·수정 시각과 버전을 가진다. 풀이와 보고서는 사용한 콘텐츠 버전, 모델 식별자와 규칙 버전을 참조한다.

## 13. 학습 데이터 흐름

1. 등록 기기에서 PIN으로 로그인한다.
2. 서버가 오늘의 계획, 콘텐츠 버전과 진행 상태를 내려준다.
3. 앱은 오늘의 학습 자료를 신뢰 기기의 IndexedDB에 저장한다.
4. 수아가 문제를 풀면 즉시 피드백을 표시하고 풀이 이벤트를 서버에 보낸다.
5. 서버는 중복을 제거하고 숙달도, 보상과 다음 추천을 계산한다.
6. 세트 완료 시 구조화된 결과를 확정하고 보호자 AI 보고서 작업을 예약한다.
7. 보호자 화면은 서버가 계산한 진도와 보고서만 조회한다.

NAS에는 정답 여부, 점수, 소요 시간, 힌트 사용, 체감 난이도와 어려웠던 스킬을 저장한다. 음성 파일과 전체 음성 전사문은 저장하지 않는다.

## 14. 오프라인과 동기화

- 서비스 워커는 앱 셸만 캐시한다.
- 오늘의 인증된 학습 자료는 신뢰 기기의 IndexedDB에 저장한다.
- 오프라인 풀이에는 기기별 고유 식별자를 붙인다.
- 재연결 시 서버는 고유 식별자로 중복 저장을 막는다.
- 콘텐츠가 수정되어도 오프라인에서 시작한 세트는 내려받은 버전으로 끝낸다.
- 기기 해제나 보호자 로그아웃 시 해당 기기의 인증 자료와 오프라인 학습 자료를 삭제한다.
- 오프라인 중에는 콘텐츠 편집, 기기 관리, LLM 작업과 보고서 생성을 허용하지 않는다.

## 15. 오류 처리

- NAS 연결 실패: 오프라인 상태와 동기화 대기 건수를 표시한다.
- 인증 만료: 오프라인 풀이를 보존하고 다시 로그인한 뒤 동기화한다.
- 중복 전송: 성공 응답을 재사용하고 새 풀이를 만들지 않는다.
- 콘텐츠 충돌: 버전 단위로 보존하고 보호자에게 충돌을 표시한다.
- 백업 실패: 보호자 첫 화면에 지속 경고한다.
- LLM 시간 초과 또는 제한: 해당 제공자의 절반만 재시도한다.
- LLM 구조 오류: 자동 게시하지 않고 수정 필요에 둔다.
- 보고서 근거 불일치: 보고서를 공개하지 않고 수정 필요로 표시한다.
- 비용 한도 초과: 새 AI 작업을 차단하고 기존 학습은 계속 제공한다.

## 16. 검증 기준

### 자동 테스트

- 보호자 로그인, 기기 등록, PIN과 잠금
- 역할별 API 접근 제한
- 진도, 숙달도와 보상 계산
- 콘텐츠 버전과 과거 풀이 보존
- 오프라인 이벤트 중복 제거
- 분야별 난이도 보정과 1~5 제한
- LLM 구조 검사, 교차 감리 상태 전이와 비용 제한
- 보고서 수치·근거 일치 검사
- 백업 생성과 복원

### 실제 환경 검증

- 13인치 갤럭시 탭 가로와 세로 화면
- 최소 터치 영역과 큰 한글 본문
- Android Chrome 마이크 권한과 읽기 흐름
- 외부 인터넷 HTTPS 접속
- DSM 5001과 내부 앱 포트의 외부 차단
- NAS 재시작 후 컨테이너 자동 복구
- 인터넷 단절 후 풀이와 재연결 동기화

Chrome 음성 인식은 브라우저와 기기 환경에 따라 달라질 수 있으므로 자동 테스트만으로 통과시키지 않고 실제 갤럭시 탭에서 확인한다.

## 17. 단계별 구현

### 1단계: 플랫폼 기반

- Node.js 컨테이너 앱과 SQLite
- Synology DDNS, HTTPS와 리버스 프록시
- 보호자 로그인, 기기 등록과 수아 PIN
- 확정된 A안 학생 화면
- 현재 한글·수학 콘텐츠 이관
- NAS 진도 저장과 여러 기기 동기화
- 읽기 전용 보호자 진도 화면
- PWA 셸, 오늘의 자료 캐시와 오프라인 풀이 대기열
- 일일 백업과 복원 절차

1단계 완료 기준은 외부 HTTPS 주소에서 새 태블릿을 보호자가 등록하고, 수아가 PIN으로 현재 국어·수학 문제를 풀며, 다른 기기의 보호자 화면에서 같은 진도를 확인하는 것이다. DSM 관리 포트는 외부에서 접근할 수 없어야 한다.

### 2단계: 콘텐츠 관리

- 보호자 문제·문장 편집
- 콘텐츠 버전과 게시 상태
- 학년·학기·단원·스킬 관리

### 3단계: 계획·보상·난이도

- 주간 계획
- 별과 실제 보상
- 적응형 숙달도와 간격 복습
- 분야별 보호자 난이도 보정

### 4단계: AI 생성과 보고서

- OpenAI와 Google API 키 설정
- 문제 분할 생성과 상호 감리
- 생성 초안 승인 흐름
- 비용 한도와 품질 지표
- 세트 및 주간 보호자 보고서

### 5단계: 1~3학년 교육과정 확장

- 국어 1~3학년 전체 단원과 스킬
- 수학 1~3학년 전체 단원과 스킬
- 단원별 진단, 복습과 평가 세트
- 생성 콘텐츠의 지속적인 보호자 승인과 품질 기록

각 단계는 별도 구현 계획과 검증을 거친다. 앞 단계의 데이터 구조와 보안 기준을 깨지 않고 확장한다.

## 18. 승인된 핵심 결정

- 공개 인터넷에서 접근 가능하지만 사이트 전체는 가족 로그인 필요
- 서비스명은 `수아의 공부방`
- Synology DDNS와 HTTPS 사용
- 컨테이너 기반 Node.js 앱과 SQLite 선택
- 보호자 비밀번호와 신뢰 기기 기반 수아 4자리 PIN
- 13인치 갤럭시 탭 가로 화면용 A안 채택
- 국어와 수학을 모두 초등학교 1~3학년까지 확장
- 보호자가 콘텐츠, 계획, 보상과 분야별 난이도를 관리
- `gpt-5.6-terra`와 `gemini-3.5-flash`가 문제를 절반씩 생성하고 서로 감리
- 보호자 승인 전 생성 문제 비공개
- 매 학습 세트와 매주 일요일 보호자 AI 보고서 생성
- 음성 파일과 전체 전사문 미저장
