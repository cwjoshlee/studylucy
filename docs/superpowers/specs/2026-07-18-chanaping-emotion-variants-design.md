# 차나핑 감정 표현 확장 설계

## 목적과 범위

학습 화면의 차나핑이 상황에 맞는 표정과 말투를 보여 주어 수아가 학습 흐름을 알아차리도록 한다. 기존의 화면 하단 플로팅 위치, 숨기기 기능, 5분 멈춤 확인 창에서 숨김 처리, 별 보상 권한 분리는 그대로 유지한다.

이번 범위는 로컬 표현만 다룬다. LLM 호출, 음성 재생, 별 지급·차감, 답안 판정 방식은 변경하지 않는다.

## 선택한 방식

상태별로 원본 독립 SVG 표정과 짧은 말풍선을 함께 바꾸는 방식을 사용한다.

- 한 장의 그림에 CSS 필터만 적용하는 방식은 표정 차이가 약하다.
- 매 키패드 입력마다 반응하는 방식은 산만하다.
- 따라서 학습 사건이 확정될 때만 `mood`를 바꾸고, 각 mood마다 독립적인 원본 SVG와 여러 문구를 둔다.

## 감정 상태와 반응

| 상황 | mood | 표정·동작 | 말투 |
| --- | --- | --- | --- |
| 정답 확정 | `celebrate` | 환하게 웃고 작은 반짝임 | 귀찮아도 인정하는 칭찬 |
| 오답 또는 재시도 | `grumble` | 살짝 삐친 눈썹과 팔짱 | 툴툴대지만 다시 풀도록 권유 |
| 2분 멈춤 | `bored` | 하품·축 늘어짐 | 지루한 듯 한 번 눌러 보자고 안내 |
| 읽기 녹음 중·확인 중 | `focus` | 조용히 귀 기울임 | 방해하지 않고 기다림 |
| 문제 열기·다음 문제·일반 대기 | `rest` | 베개에 기대어 느긋함 | 가볍게 시작·다음 문제를 권유 |

`grumble`의 문구는 예를 들어 “아… 그건 아니잖아. 다시 천천히 해보자, 차나~!” 수준의 툴툴거림을 허용한다. 아이를 능력으로 평가하거나 모욕하는 표현, 별 차감·벌·포기 유도는 사용하지 않는다. 모든 문구는 45자 이하이며 각 mood에는 최소 세 가지 문구를 둔다.

## 데이터 흐름과 화면 동작

`ChanaPingEvent`는 계속 공유 학습 계약에 남기고, 클라이언트의 순수 함수가 event를 mood로 변환한다. `ChanaPingCoach`는 mood에 맞는 로컬 SVG와 결정적으로 선택한 문구를 표시한다.

- 정답/재도전/2분 멈춤/녹음 시작·종료/다음 문제처럼 의미 있는 상태 변화에만 갱신한다.
- 숫자 키패드 한 자리 입력, 포인터 이동, 네트워크 대기에는 표정이나 문구를 갱신하지 않는다.
- 재도전 횟수와 문제 식별자를 선택 키에 포함해 같은 재도전에서 깜빡이지 않고, 새 재도전에서는 다른 문구를 고를 수 있게 한다.
- 확인 대화상자가 표시되는 동안에는 코치 전체를 렌더링하지 않는다.

모든 SVG는 자체 제작한 작은 로컬 파일이며, 외부 URL·스크립트·제공받은 프랜차이즈 이미지 원본을 포함하지 않는다. 태블릿에서는 오른쪽 아래 플로팅, 700px 미만에서는 본문 아래 전체 너비로 표시하는 기존 반응형 규칙을 유지한다. 라이브 영역은 한 개의 polite 상태 알림만 유지한다.

## 오류와 검증

표정 asset이 예상과 다르더라도 답안 저장·별·멈춤 기록에는 영향을 주지 않는다. 테스트는 다음을 확인한다.

- event-to-mood 매핑과 각 mood별 복수의 안전 문구
- 오답에는 `grumble`, 정답에는 `celebrate`, 2분 멈춤에는 `bored` asset이 선택됨
- 키패드 입력만으로 문구·표정이 바뀌지 않음
- 확인 창에서는 코치가 사라짐
- 새 SVG가 로컬·작고 외부/실행 가능한 콘텐츠가 아님
- 접근 가능한 대체 텍스트와 하나의 polite 상태 알림
