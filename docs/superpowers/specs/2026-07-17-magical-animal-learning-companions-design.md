# 수아의 마법 동물 학습 친구와 유머 경험 설계

## 상태

- 작성일: 2026-07-17
- 적용 브랜치: `codex/platform-foundation`
- 선행 상태: 플랫폼 기반과 배포 전 권위·오프라인 강화 구현 및 독립 검토 완료
- 디자인 선택: 별토끼를 중심으로 과목별 성격이 다른 오리지널 동물 친구 팀

## 1. 목적

수아가 국어와 수학을 어려운 시험이 아니라 친한 동물 친구와 함께 푸는 짧은
모험처럼 느끼게 한다. 마법 동화 분위기, 동물의 엉뚱한 행동과 짧은 말장난을
사용하되 학습 본문과 정답 판단을 가리지 않는다. 기존 별 원장, 오프라인 보존,
보호자 권위와 학습 저장 계약은 그대로 유지한다.

성공한 화면은 다음 조건을 모두 만족한다.

1. 홈과 학습 화면에서 이름과 성격이 다른 네 동물 친구를 알아볼 수 있다.
2. 학습 시작, 정답, 다음 문제, 오래 생각하는 상태에는 짧고 반복이 적은 유머가
   나온다.
3. 오답, 읽기 실패와 저장 실패는 수아를 웃음의 대상으로 삼지 않고 구체적인
   도움을 준다.
4. 국어 문장과 수학 문장제의 인지 부담을 현재 화면보다 낮춘다.
5. 초기 국어·수학 콘텐츠와 어린이용 힌트는 모두 자연스러운 한국어이며,
   유머러스한 동물 사건을 포함한다.
6. 13인치 Galaxy Tab 가로·세로 화면에서 핵심 조작과 문장이 한눈에 보인다.

## 2. 범위

이번 구현은 현재 게시되는 초기 국어 10개와 수학 10개를 대상으로 다음을
완성한다.

- 오리지널 마법 동물 친구 네 명과 접근성 대체 설명
- 홈의 친구 무대, 과목별 인사와 `오늘의 우당탕 사건`
- 학습 화면의 상태별 친구 반응과 단계별 힌트
- 국어 문장 덩어리, 핵심 낱말과 수학의 숫자·질문·단위 분리 표시
- 현재 초기 콘텐츠 20개의 동물 유머 이야기 개작과 영어 힌트 제거
- 정답 축하의 캐릭터 반응과 오답의 비유머 지원 경계
- 모션 감소, 오프라인, 권위 실패와 콘텐츠 누락 시 안전한 대체 동작
- Galaxy Tab 크기의 실제 브라우저 시각·상호작용 검증

이 구조는 후속 1~3학년 전체 콘텐츠와 보호자 콘텐츠 편집, LLM 배치 생성에서
재사용한다. 그러나 이번 구현에서 1~3학년 전체 교육과정, 자유형 어린이 AI
대화, 음성 합성, 보호자용 유머 편집기나 새 보상 경제를 만들지는 않는다.

## 3. 저작권과 어린이 안전 원칙

- 기존 상업 캐릭터의 이름, 상표, 얼굴, 색 배치, 소품, 고유 실루엣과 세계관을
  복제하지 않는다.
- 시각 자산은 새 이름과 독창적인 형태를 가진 오리지널 파스텔 마법 동물로
  제작한다.
- 웃음의 대상은 캐릭터의 실수와 엉뚱한 행동이다. 수아의 오답, 발음, 읽기
  속도, 외모, 능력, 가족과 감정을 농담 소재로 사용하지 않는다.
- 오답과 읽기 실패 직후에는 유머를 금지하고 공감, 문제의 핵심과 다음 행동만
  제공한다.
- 비꼼, 겁주기, 비교, 수치심, 실패 횟수 조롱, 벌을 암시하는 대사를 금지한다.
- 자동 음성, 광고, 외부 추적과 자유형 AI 채팅을 어린이 화면에 넣지 않는다.
- 별 차감 문구는 기존 감사 가능한 서버 결과를 그대로 설명하며 캐릭터가 수아를
  혼내지 않는다.

## 4. 마법 동물 친구

### 별토끼 루미

- 역할: 홈의 주 안내자, 모든 과목의 정서적 기준점
- 성격: 다정하고 침착하지만 별 지팡이가 자주 딸꾹질한다.
- 유머: 별 대신 양말, 당근 모양 구름이나 작은 비눗방울이 나오는 몸개그
- 색: 크림, 연보라, 금빛
- 대체 설명: `작은 망토와 별 지팡이를 든 크림색 토끼 루미`

### 수달 또또

- 역할: 국어와 낱말 친구
- 성격: 낱말을 소중히 모으지만 주머니 속 생선 간식과 자주 헷갈린다.
- 유머: 비슷한 소리의 낱말, 엉뚱한 물건 이름표와 젖은 수첩
- 색: 밤색, 민트, 산호색
- 대체 설명: `낱말 수첩과 조개 연필을 든 수달 또또`

### 너구리 모모

- 역할: 수학과 문장제 친구
- 성격: 숫자를 좋아하고 꼬리 줄무늬까지 세지만 과자를 식에 끼워 넣곤 한다.
- 유머: 숫자 카드가 머리에 붙거나 주판 알 대신 포도알을 올리는 실수
- 색: 회갈색, 하늘색, 노란색
- 대체 설명: `숫자 가방과 포도알 주판을 든 너구리 모모`

### 아기용 봉봉

- 역할: 정답 축하, 짧은 휴식과 다음 문제 전환
- 성격: 용감하게 불을 뿜으려 하지만 비눗방울과 별가루가 나온다.
- 유머: 재채기 뒤 왕관이 거꾸로 씌워지고 꼬리에 리본이 감기는 몸개그
- 색: 복숭아색, 청록색, 금빛
- 대체 설명: `별가루 비눗방울을 내뿜는 복숭아색 아기용 봉봉`

친구들은 학생 데이터를 의인화해 평가하지 않는다. `모모가 숫자 7을 과자
봉지에 넣었대`는 허용하지만 `수아도 7을 잊었네`는 금지한다.

## 5. 상태별 유머 계약

`CompanionMoment`는 다음 닫힌 집합을 사용한다.

- `home-welcome`: 오늘 처음 홈을 열 때의 인사
- `home-return`: 학습 뒤 홈으로 돌아왔을 때
- `lesson-open`: 문제를 처음 열 때의 상황극
- `thinking`: 2분 무반응 안내
- `correct`: 정답과 완료 축하
- `next`: 다음 문제 이동
- `offline`: 네트워크 없이 검증된 학습을 진행하는 상태
- `retry`: 오답 또는 읽기 실패
- `save-wait`: 저장 또는 동기화를 기다리는 상태
- `idle-confirm`: 4분 계속 여부 확인
- `idle-paused`: 5분 결과와 재개 안내

유머가 허용되는 상태는 `home-welcome`, `home-return`, `lesson-open`,
`thinking`, `correct`, `next`다. `offline`은 가벼운 여행 비유만 허용하되 저장
완료를 주장하지 않는다. `retry`, `save-wait`, `idle-confirm`, `idle-paused`는
유머를 금지한다.

한 화면은 동시에 한 친구의 한 말풍선만 표시하며 문구는 두 문장을 넘지 않는다.
같은 날짜, 학생, 문제, 상태는 같은 cue를 선택한다. React 재렌더나 새로고침으로
문구가 흔들리지 않으며, 문제와 상태가 바뀌면 다음 후보로 넘어갈 수 있다.

## 6. 화면 설계

### 홈: 13인치 가로 A안

기존 세 열을 유지하되 역할을 분명히 한다.

- 왼쪽 `마법 친구 쉼터`: 네 친구의 작은 초상과 현재 말하는 친구의 큰 그림,
  이름, 한 개의 말풍선
- 중앙 `오늘의 학습`: 필수·선택 카드를 유지하고 과목 친구, 예상 소요, 별 상태,
  `오늘의 우당탕 사건` 한 줄을 추가
- 오른쪽 `별과 오늘의 흔적`: 확정 별, 동기화 대기 수, 오늘 만난 친구와 완료한
  마법 걸음

학습 카드의 버튼과 핵심 상태는 기존 48px 이상 터치 영역을 유지한다. 완료 카드는
과도한 색종이 대신 봉봉의 작은 비눗방울 배지와 `함께 해결했어요`를 표시한다.

### 세로와 좁은 화면

친구 쉼터는 중앙 상단의 가로 친구 띠로 바뀐다. 말풍선, 필수 학습, 별 현황,
선택 학습 순서로 배치한다. 친구 그림을 완전히 숨기지 않으며 텍스트와 핵심
버튼보다 먼저 화면을 독점하지 않는다.

### 학습 화면

학습 화면은 한 활동만 보여 주는 기존 원칙을 유지한다.

1. 상단에 과목 친구의 작은 그림, 이름과 `lesson-open` 말풍선
2. 과목·단원·난이도 칩과 문제 제목
3. 학습 본문과 읽기 조작
4. 과목별 이해 보조 영역
5. 답, 피드백, 힌트와 다음 행동
6. 정답일 때만 봉봉 축하와 별 지급 결과

친구 영역은 학습 본문보다 시각적 우선순위가 낮고, 화면 읽기 순서도 문제 제목과
본문을 방해하지 않는다.

## 7. 국어와 수학의 인지 부담 완화

### 국어

- 문장부호 기준으로 본문을 문장 카드로 나눈다.
- 목표 `tokens`를 `오늘 만날 낱말` 칩으로 먼저 보여 준다.
- 읽기 실패 후 놓친 낱말만 강조하고 `다시 읽을 표현`을 한국어로 설명한다.
- 한 번에 모든 설명을 열지 않고 `낱말 힌트` 버튼으로 단계적으로 공개한다.
- 음성 인식이 없을 때의 수동 입력은 대체 수단으로 유지하되 화면의 주인공처럼
  보이지 않게 접을 수 있는 보조 영역으로 둔다.

### 수학

- 이야기 본문 아래에 등장 숫자를 원문 순서대로 `숫자 단서` 칩으로 표시한다.
- 질문은 별도의 `무엇을 구할까?` 카드로 분리한다.
- 단위는 답 입력 옆에 고정하고, 숫자 입력 전에는 정답 여부를 암시하지 않는다.
- 첫 오답은 기존 `checkHint`를 자연스러운 한국어로 제공한다.
- 반복 오답은 `두 수 찾기 → 어떤 계산인지 말하기 → 계산하기`의 세 단계 중
  다음 한 단계만 보여 준다.

분절 표시는 원문을 바꾸지 않는다. 서버 채점, `tokens`, 정답, 콘텐츠 버전과
읽기 판정에는 기존 원문을 사용한다.

## 8. 콘텐츠 모델

`LearningItemPayload`에 선택적인 `delight`를 추가한다.

```ts
type CompanionId = "lumi" | "toto" | "momo" | "bongbong";

type LearningDelight = {
  companion: CompanionId;
  mishap: string;
  openingCue: string;
  celebrationCue: string;
};
```

- 모든 문자열은 앞뒤 공백을 제거한 1~120자의 한국어 어린이 문구다.
- `mishap`은 홈 카드의 `오늘의 우당탕 사건`에 사용한다.
- `openingCue`는 문제를 처음 열 때만 사용한다.
- `celebrationCue`는 서버가 신규 완료 또는 신규 별 지급을 확인했을 때만 쓴다.
- 기존 콘텐츠와 복구 계획의 payload에 `delight`가 없으면 과목별 안전한 cue
  카탈로그를 사용한다.
- 선택 필드 추가이므로 기존 SQLite 콘텐츠, 백업과 오프라인 캐시는 마이그레이션
  없이 읽을 수 있다.

초기 seed 20개는 모두 `delight`를 가진다. 국어 10개는 한 편의 `또또의 젖지
않는 낱말 수첩` 연작이고, 수학 10개는 `모모의 포도알 주판 소동` 연작으로
개작한다. 단계가 올라가도 문장 길이만 급격히 늘리지 않고 낱말, 수와 사고 단계가
점진적으로 어려워지게 한다. 모든 `hint`와 `checkHint`는 한국어로 바꾼다.

## 9. 컴포넌트와 경계

### 순수 데이터 계층

- `src/client/companions/cast.ts`: 캐릭터 메타데이터와 타입
- `src/client/companions/cues.ts`: 상태별 문구와 결정적 선택 함수
- `src/client/learning/problem-breakdown.ts`: 문장·숫자·단위의 표시 전용 분절

이 계층은 React, 네트워크와 IndexedDB에 의존하지 않는다.

### 표현 계층

- `src/client/companions/companion-avatar.tsx`: 오리지널 그림과 대체 설명
- `src/client/companions/friend-stage.tsx`: 홈 친구 쉼터
- `src/client/companions/learning-companion.tsx`: 학습 상태별 한 개의 말풍선
- `src/client/learning/problem-breakdown.tsx`: 국어·수학 이해 보조 표시

`StudentHome`은 계획·별·큐 상태를 계속 소유하고 친구 컴포넌트에는 표시용 props만
준다. `LearningSession`은 권위, 읽기, 답, 무반응과 저장 상태를 계속 소유하며
그 상태를 `CompanionMoment`로 좁혀 전달한다. 친구 컴포넌트는 풀이를 저장하거나
별을 계산하지 않는다.

### 시각 자산

네 캐릭터는 오리지널 파스텔 마법 동물 일러스트로 제작하고
`public/assets/companions/`에 웹용으로 최적화한다. 각 파일은 캐릭터별 안정된
경로, 폭·높이와 대체 설명을 가진다. 자산을 읽지 못하면 이름 이니셜과 CSS 색상
배지가 표시되어 학습 기능은 계속 동작한다.

## 10. 데이터 흐름

홈은 서버가 확정한 `TodayPlan`, 별 요약과 로컬 큐 수를 받은 뒤 오늘 날짜,
문제 ID, 완료 상태를 cue 선택 키로 전달한다. cue 선택은 표시만 바꾸며 네트워크
요청이나 저장을 만들지 않는다.

학습 화면은 다음 순서를 지킨다.

1. 서버 학습 세션 발급 성공 또는 검증된 오프라인 진입
2. `lesson-open` cue 표시
3. 읽기와 수학 답 처리
4. 서버 `AttemptReceipt` 또는 오프라인 보존 결과 수신
5. 실패이면 `retry` 지원 문구, 신규 완료이면 `correct` 축하
6. 다음 문제 또는 홈으로 이동

별 축하는 기존 `starAward.awarded`와 `eventId`를 유일한 권위로 유지한다. 친구
cue는 별 지급을 추측하지 않는다.

## 11. 오류와 대체 동작

- 일러스트 누락: 텍스트 배지와 대체 설명으로 계속 표시
- `delight` 누락: 과목별 기본 친구와 결정적 cue 사용
- 잘못된 `delight`: 공유 Zod 스키마에서 콘텐츠 게시·seed 검증 실패
- 네트워크 `TypeError`: 기존 오프라인 자격이 있으면 `offline`, 없으면 기존
  권위 실패 동작으로 화면 종료
- 저장 대기: `학습 기록이 아직 여행 중이에요. 연결되면 확인할게요.`처럼
  미확정임을 명시
- 명시적 4xx, 로그아웃, 기기 해제: 기존 권위 전이를 그대로 따르고 친구 화면이
  이를 가리지 않음
- `prefers-reduced-motion: reduce`: 이동·튀기·회전·입자 효과 제거
- 긴 한국어, 200% 확대: 말풍선이 자르고 숨기지 않고 세로로 늘어남

## 12. 성능과 오프라인

- 첫 화면에 필요한 캐릭터 자산만 앱 셸과 함께 캐시한다.
- 네 캐릭터 전체 자산 예산은 압축 후 600KB 이하, 한 파일 180KB 이하를 목표로
  한다.
- cue와 분절 로직은 동기 순수 함수이며 렌더 중 네트워크나 난수를 사용하지 않는다.
- PWA 업데이트 뒤에도 기존 캐시 계획의 `delight` 누락 대체가 동작한다.
- 오프라인 큐, 복구 계획, 활동 cursor와 별 원장 구조는 변경하지 않는다.

## 13. 테스트와 인수 기준

### 순수 단위 테스트

- 캐릭터 ID별 메타데이터, 고유 이름과 대체 설명
- 같은 키의 cue 결정성, 다른 상태의 허용된 변화
- `retry`, `save-wait`, `idle-confirm`, `idle-paused`에 유머 cue가 없는 계약
- 한국어 문장 분절과 수학 숫자·질문·단위 추출이 원문을 변경하지 않는 계약
- `delight`의 길이, 문자와 허용 캐릭터 검증

### 컴포넌트 테스트

- 홈에 네 친구, 현재 친구 한 명과 한 말풍선만 존재
- 국어·수학 카드의 올바른 친구와 우당탕 사건
- 읽기 실패와 수학 오답에서 공감·구체 힌트만 표시
- 정답과 신규 별 지급에서 봉봉 축하가 한 번만 표시
- 오프라인·저장 대기·명시적 권위 실패 문구가 결과를 과장하지 않음
- 모션 감소에서 입자와 변형이 없음
- 모든 주요 버튼 48px 이상과 접근 가능한 이름

### 콘텐츠 검사

- 초기 20개 모두 한국어 `hint`, 수학 `checkHint`, `delight` 보유
- 어린이 화면 문자열에 `PASS`, `FAIL`과 영어 지시문이 없음
- 금지된 상업 캐릭터 이름과 수아를 조롱하는 표현이 없음
- 국어·수학 각각 최소 10개의 서로 다른 사건과 축하 문구

### 브라우저 인수

- 1368×912와 1600×900 가로 화면에서 홈, 국어, 수학, 오답, 정답
- 800×1280 세로 화면에서 친구 띠, 필수 학습, 별 현황, 선택 학습 순서
- 실제 클릭으로 PIN 로그인 뒤 학습 시작, 힌트, 오답, 정답, 다음 문제
- 200% 확대와 `prefers-reduced-motion`에서 잘림과 조작 불능 없음
- 홈과 문제 화면의 스크린샷을 남겨 캐릭터 중복, 겹침과 과도한 시각 소음을
  검토

### 회귀 검증

- Node 22/npm 11.11.0의 전체 `npm run check`
- 모든 셸 스크립트 `bash -n`
- 기존 권위, 오프라인, 별, 백업 테스트 전부 통과
- `git diff --check`와 tracked worktree clean

## 14. 완료 판단

구현 완료는 단순히 캐릭터 그림을 추가한 상태가 아니다. 초기 20개 콘텐츠의 실제
학습 흐름에서 친구가 맥락에 맞게 등장하고, 국어·수학의 정보 구조가 더 명확하며,
오답에는 유머가 없고 정답에는 짧은 축하가 있고, Galaxy Tab 크기의 실제
브라우저 증거와 전체 회귀 검증이 모두 있어야 한다. NAS 외부 배포와 실물 태블릿
조작은 별도 운영 게이트로 `NOT RUN`을 유지하고 코드 완료와 혼동하지 않는다.
