# Android 태블릿 사용 가이드

## 권장 환경

- 브라우저: Chrome for Android
- 접속 방식: Synology DDNS의 HTTPS 주소
- 사용 방식: Chrome 메뉴에서 "홈 화면에 추가" 또는 "앱 설치"
- 화면 방향: 가로 화면 기준 (13인치 Galaxy Tab), 세로/휴대전화는 반응형 보조 지원

## 왜 Chrome이 중요하나

현재 앱은 Chrome 브라우저 음성인식으로 아이가 읽은 문장을 전사합니다. 별도 LLM이나 앱 자체 외부 STT API를 쓰지 않으며, 음성 파일과 전체 전사문을 서버에 보내거나 저장하지 않습니다.

Chrome 음성인식은 브라우저 기능에 의존합니다. 기기, 브라우저 버전, 마이크 권한, 네트워크 상태에 따라 전사 결과가 없거나 부정확할 수 있으므로 수동 입력 판정 경로를 남겨두었습니다.

## 설치 후 테스트 순서

1. Android 태블릿의 Chrome에서 배포 URL을 엽니다.
2. Chrome 메뉴에서 홈 화면에 추가 또는 앱 설치를 선택합니다.
3. 홈 화면의 "수아의 공부방" 아이콘으로 앱을 엽니다.
4. 보호자가 현재 기기를 등록한 뒤 수아의 4자리 PIN으로 로그인합니다.
5. 오늘의 필수 학습 4개 중 하나를 눌러 학습 화면을 엽니다.
6. 국어에서 "읽기 시작"을 누르고 마이크 권한을 허용한 뒤, 빨간 듣기 표시·경과 시간·항상 보이는 `읽기 멈추기` 버튼을 확인합니다.
7. 첫 음성 결과 뒤 3초 동안 새 결과가 없으면 자동으로 채점되는지 확인합니다. 결과가 전혀 없으면 15초에 안내가 나오고, 세션은 최대 45초에 끝나야 합니다. 아이가 원하면 `읽기 멈추기`로 먼저 마칠 수 있습니다.
8. 85점 이상이고 빠진 핵심 표현이 없을 때 읽기 통과가 표시되고 1.5초 뒤 다음 문제로 자동 이동하는지 확인합니다.
9. 계산 문제는 읽기 통과를 요구하지 않고 바로 큰 숫자 키패드를 보여야 합니다. 최대 두 자리 답을 0~9·지우기·답 확인으로 입력하며, 음성 인식·녹음·수동 전사 입력은 표시하지 않습니다.
10. 계산 답이 틀리면 다음 문제 버튼이 잠겨 있고 정답 뒤에만 열리는지 확인합니다.
11. 필수 완료 뒤 대시보드에서 완료 표시와 서버 확정 별 잔액이 갱신되는지 확인합니다.
12. 오프라인일 때 대기 별과 확정 잔액이 합쳐지지 않는지 확인합니다.
13. 다음 날 다시 열었을 때 새 날짜의 서버 일일 계획이 표시되는지 확인합니다.
14. 두 번째 등록 기기에서 먼저 한 문제를 완료한 뒤 첫 기기의 오프라인 풀이와 무반응을 재연결합니다. 풀이는 보존되고 순서 충돌 무반응은 차감되지 않는지 확인합니다.
15. 보호자 기기 관리에서 첫 기기를 해제해 학생 화면과 학습 API가 차단되는지 확인합니다. 같은 Galaxy Tab을 재등록하고 PIN 로그인한 뒤 풀이만 복구되고 무반응은 면제되는지 확인합니다.

실기기 인수에서는 Galaxy Tab을 가로로 두고 CSS viewport를 기록합니다. 핵심 버튼·입력칸의 실제 터치 영역 최솟값이 가로와 세로 모두 48px 이상인지 측정하고, 외부 키보드의 Tab/Shift+Tab 이동 순서와 `:focus-visible` 표시를 화면 캡처 또는 측정표로 남깁니다.

## Step-up 인수 체크리스트

- [ ] 1368×912 landscape: left navigation rail visible, floating menu hidden.
- [ ] 800×1280 portrait: floating menu visible, left navigation rail hidden.
- [ ] Resize/rotation keeps the current typed answer and AI menu leaf.
- [ ] Wrong challenge response shows 도전 시도 완료 and next item opens.
- [ ] All challenge responses correct: exactly one CHALLENGE_PERFECT ledger event appears.
- [ ] A typed dictation can finish with the keyboard only.
- [ ] An API key is never shown after saving.

## Step-up 릴리스 하드닝 인수

아래 여섯 항목은 자동 테스트 결과와 실제 화면 확인을 함께 기록한다. 아직 확인하지 않은 항목은 `NOT RUN`으로 남기며, 로컬 검증만으로 NAS 배포 완료로 표시하지 않는다.

- [ ] 기초를 마치기 전 현재·도전 문제를 직접 제출하면 `STEP_LOCKED`가 반환되고, 시도·별·진도는 늘지 않는다.
- [ ] 어느 기기에서든 오늘의 일일 계획을 한 번 받은 뒤 보호자가 같은 날짜의 요구량을 바꾸면 `PLAN_LOCKED`가 반환된다.
- [ ] 운영 환경의 HTTP API 키 저장은 `HTTPS_REQUIRED`로 거부되고, 저장 응답과 다시 연 설정 화면 어디에도 키 문자열이 보이지 않는다.
- [ ] 보호자 AI 학습실에 이번 달 예상 예산과 사용액, 제공자별 예상 입력·출력 단가가 표시되고 정수 값으로 저장된다.
- [ ] 문제 생성 중 과목이나 단계를 바꾸면 늦게 도착한 이전 결과가 화면에 나타나거나 발행되지 않는다.
- [ ] 다른 화면으로 숨긴 정답 결과는 자동으로 다음 문제로 넘어가지 않고, 휴식 화면은 `학습 계속`에 초점을 두며 재개 뒤 보이는 호출 버튼으로 초점을 돌려준다.

## 실기기 증거 기록

실제 측정 전에는 전부 `NOT RUN`으로 둡니다. 자동 브라우저 테스트를 실기기 PASS로 옮겨 적지 않습니다.

| 항목 | 상태 | 증거 |
|---|---|---|
| 모델/Android/Chrome 버전 | NOT RUN | - |
| 가로 CSS viewport | NOT RUN | 너비×높이 |
| 핵심 터치 대상 최솟값(>=48px) | NOT RUN | 요소 이름/너비×높이 |
| Tab/Shift+Tab 순서와 `:focus-visible` | NOT RUN | 캡처 파일명 |
| 오프라인 대기→재연결 | NOT RUN | 대기 수/확정 별 전후 |
| A/B stale cursor와 idle 면제 | NOT RUN | cursor/원장 사유 |
| 기기 해제→재등록→PIN recovery | NOT RUN | 상태 코드/화면 이름 |

## 운영 팁

- 아이가 쓰는 기기에서는 Chrome을 기본 브라우저로 쓰는 편이 좋습니다.
- 첫 사용 전 태블릿 볼륨과 마이크 권한을 확인합니다.
- 국어 음성 인식은 첫 결과 뒤 3초 무음이면 자동으로 마치고, 무결과 15초 안내와 전체 45초 상한을 적용합니다. 필요하면 언제든 `읽기 멈추기`를 누릅니다.
- 국어 읽기 통과 뒤에는 1.5초 후 다음 문제로 자동 이동합니다.
- 읽기 PASS는 85점 이상과 핵심 표현 누락 없음이 함께 필요합니다.
- 한글 단락은 읽기 통과가 필요하지만, 계산 문제는 읽기 통과를 요구하지 않고 큰 숫자 키패드의 정답만 확인합니다.
- 문제 순서, 진도와 별은 서버가 날짜별로 관리하므로 여러 등록 기기에서 같은 확정 상태가 보입니다.
- 음성 판정 점수보다 "어떤 표현을 다시 읽었는지"를 더 중요하게 봅니다.
- Chrome 전사가 이상하면 아이를 다시 평가하지 말고, 수동 입력으로 확인합니다.
- 이 화면은 진단이 아니라 읽기 연습 기록용입니다.
